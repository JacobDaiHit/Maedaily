# 第 2 章：轨迹奖励、信用分配与训练系统

> 前置：[第 1 章](01_从单轮RLVR到多步交互.md)、[Actor–Critic 与 GAE](../../RL/chapters/06_ActorCritic与GAE.md)。目标：把一条轨迹连到真实更新，发现奖励、mask 和数据版本的错误。

沿用上一章的两次搜索例子：第一次查城市，第二次查货币，最后答对。现在只在末尾给 1 分，模型虽知道整条轨迹成功，却不知道哪次搜索不可或缺。我们先定义每一步收到的分数，再谈怎样把最终结果用于更新。这正是**信用分配**：把延迟出现的结果与先前动作联系起来；它不是自动得到每一步的因果贡献。

第一次阅读先只取折扣因子为 1：两次搜索各花 0.05 分，答对加 1 分，那么整条轨迹净得 $1-0.05-0.05=0.90$。从第二次搜索之前看，后面只剩“一次扣分 + 答对”，回报为 0.95。后面的 $G_t$ 公式只是把这种“从第 $t$ 步往后合计”写成通式；PPO 损失可以第二遍再读。

## 2.1 正确率与资源消耗是不同目标

从题目开始到结束叫一个**回合**。设回合内共做 $T$ 次决策；第 $t$ 次动作之后收到的单步**奖励**为 $r_t$。从这一步往后得到的累计奖励叫**回报** $G_t=\sum_{k=t}^{T-1}\gamma^{k-t}r_k$，其中 $\gamma\in[0,1]$ 是折扣因子：越靠后的奖励乘越高次幂。若只关心有限回合的最终正确率，可取 $\gamma=1$，在最后回答时给 0 或 1。若定义 $R=I_{\mathrm{correct}}-cN_{\mathrm{tool}}$，$I_{\mathrm{correct}}$ 在答对时为 1、否则为 0，$N_{\mathrm{tool}}$ 是调用次数，$c$ 是每次调用的成本，那么优化目标同时考虑正确与节约调用；它已不是单纯正确率。

教学轨迹有两次搜索，各扣 0.05，最后正确得 1。取 $\gamma=1$，奖励序列 $[-0.05,-0.05,1]$ 对应回报 $[0.90,0.95,1]$。最后一步应由“回答之后的奖励”计入，不能偏移到不存在的下一条记录。改变 $c$ 是改变偏好取舍，不能当成无关紧要的稳定训练技巧。

## 2.2 给所有 token 一个分数不等于完成归因

最简单的方法是把最终奖励用在所有模型动作上，但它往往有很大**方差**：同样的失败分数可能来自早期查询错误、最后读错文档或工具故障，单条轨迹难以区分。令 $V(H_t)$ 估计在历史 $H_t$ 后继续执行的平均回报，定义**优势** $A_t=G_t-V(H_t)$；它表示这次实际结果比该历史下的预期好多少。减去这个基线有助于降低梯度估计方差，却不构成“这次查询造成成功”的因果证明。

组内相对奖励比较同题多条轨迹，可以学习哪条轨迹更好，却未必分清轨迹内部哪些步骤有用。Agent Lightning 原稿虽然提供调用级信用分配接口，其默认实现仍将同一终局回报赋给每次调用；更精细的价值分配是扩展方向。[论文 §3.3](https://arxiv.org/html/2508.03680v1) 把模块名当成问题已解决，会误读贡献。

过程奖励提供更密反馈，但“找到相关文档”与“最后正确作答”并不等价。若每次搜到重复证据都得分，模型可能反复查询而不回答。先检查奖励是否鼓励目标行为，再讨论优化器。反事实比较同一前缀下不同查询可以研究归因，但需要额外 rollouts，且比较依赖后续策略和环境可重放性。

## 2.3 从轨迹到 token loss

训练器会一次处理一个**批次**，其中有 $B$ 条轨迹；短轨迹用无效的 padding 位置补到长度 $L$，所以逐 token 的对数概率、优势和损失掩码可整理成 $[B,L]$。下标 $b$ 指第几条轨迹，$i$ 指其中第几个 token。$h_{bi}$ 是生成该 token 时实际使用的上下文，$y_{bi}$ 是生成的 token。若同一批旧轨迹被用于更新，$\pi_{\mathrm{old}}$ 指当时采样轨迹的旧策略，$\pi_\theta$ 指正在更新的策略；两者给同一 token 的概率之比为 $\rho_{bi}=\exp(\log\pi_\theta(y_{bi}\mid h_{bi})-\log\pi_{\mathrm{old}}(y_{bi}\mid h_{bi}))$。$\epsilon$ 是允许比率偏离 1 的裁剪范围。用这些量可写出一种全批 token 平均的 PPO 损失：

$$
\mathcal L=-\frac{\sum_{b,i}m_{bi}\min\{\rho_{bi}A_{bi},\operatorname{clip}(\rho_{bi},1-\epsilon,1+\epsilon)A_{bi}\}}{\sum_{b,i}m_{bi}}.
$$

式中 $m_{bi}$ 是上一章定义的损失掩码，$A_{bi}$ 是分配到该 token 的优势，$\operatorname{clip}$ 把概率比率限制在 $[1-\epsilon,1+\epsilon]$ 后再参与保守更新；负号表示把“希望增大的量”改写成要最小化的损失。这里暂略 KL 散度正则项，即用于衡量并限制两个策略分布差异的项；优势不再对当前参数求梯度，且分母必须非零。空输出或全零 mask 要单独处理。这只是明确选择的一种归约，先按轨迹平均再按批次平均会改变长短轨迹权重。**参考策略**是另一个可选的约束参照，用于限制偏离初始模型；它与采样用的旧策略不是同一个角色。公式来源与变体见 [PPO](../../RL/chapters/07_TRPO与PPO.md)和[GRPO](../../post_train/chapters/06_GRPO与RLVR.md)。

损失为零的工具位置仍可能占大部分上下文；因此“训练 token 很少”不保证显存低。切成逐调用样本可以减轻某些长序列成本，却可能反复处理重叠历史，需要实测总输入 token 和吞吐。

## 2.4 终止与截断怎样进入计算

调用级 TD 目标可写为 $r_t+\gamma(1-d_t)V(H_{t+1})$，其中 $d_t=1$ 只表示任务真正终止。若只是工程截断，任务仍可继续，价值法通常需要尾部自举。没有 critic 的终局奖励算法不能凭空补出准确尾值：应预先规定预算内成功目标、补完回合、丢弃并披露选择偏差，或引入经过检验的估计。把所有超长轨迹直接记错同样是一种目标选择。[时间限制原理](https://gymnasium.farama.org/tutorials/gymnasium_basics/handling_time_limits/)

## 2.5 rollout 版本滞后是统计问题

一次训练循环是“固定策略版本采样 → 工具执行 → 奖励 → 整理样本 → 更新 → 同步权重”。异步系统中，训练器可能已到版本 $v+3$，缓慢工具轨迹仍来自 $v$。保存行为策略版本、原始 log-prob、采样温度、tokenizer 与工具版本才能审计差异。

PPO 的 token 概率比率控制局部更新，不自动精确修正整条旧轨迹的状态分布偏移。完整重要性采样还涉及轨迹概率乘积，在长时域可能方差很大。应限制样本年龄、测量版本滞后和 clipping 比例，并做同步基线；不能把“用了 PPO”当成任意 off-policy 数据都可靠的保证。运行与训练解耦便于扩展，也让这些边界更需要明示。[Agent Lightning 系统设计](https://arxiv.org/html/2508.03680v1)

## 2.6 手算与实现检查

1. 上述奖励改用 $\gamma=0.9$，第一个回报是多少？**答案：**$-0.05-0.045+0.81=0.715$。
2. 当前奖励 $-0.05$，尾值 $0.8$，$\gamma=0.9$，真终止和工程截断的 TD 目标分别是多少？**答案：**$-0.05$ 与 $0.67$。
3. 两个模型行动 token 的 log-prob 为 $-0.2,-0.3$，中间工具 token 为 $-9$，优势均为 1，计算未裁剪负 score 的 token 平均。**答案：**$0.25$；错把工具算进去得到 $9.5/3$。见[可运行核算实验](../experiments/README.md)。
