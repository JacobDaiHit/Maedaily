## 1. 语言模型到底在预测什么

看到“我爱”，模型需要给可能的下一个片段分配概率，例如“数学”“音乐”或其他内容。它不是每次只输出一个判断，而是给整个词表中的候选分别打分；生成时再按规则选择一个候选，接到已有文本后继续预测。这个反复使用前缀生成后续内容的过程，叫自回归生成。

训练时我们已经知道完整文本，可以同时构造多个练习：给定开始符号预测“我”，“我”之后预测“爱”，“我爱”之后预测“数学”。为了让这些练习在一张计算图里批量处理，又不提前看答案，需要因果注意力。Transformer 是模型结构的名称；本课用 PyTorch 自己实现其小型版本，不要求先安装名为 `transformers` 的另一个软件包。

## 2. 文字不能直接做矩阵乘法

先约定一个教学词表：`<PAD>=0,<BOS>=1,<EOS>=2,我=3,爱=4,数学=5`。尖括号中的三个特殊符号分别表示补齐位置、序列开始、序列结束。人为把“我爱数学”切为 `我 / 爱 / 数学`，再加开始与结束标记，得到编号 `[1,3,4,5,2]`。

切分规则叫分词器规则，得到的片段叫 token。真实分词器可能把一个汉字、多个字或部分字节作为一个 token；本课的手工切分只是为了看清数据流，不代表中文语言模型都采用这种词表。编号 5 只是“数学”所在的行号，不能说它的意义比编号 3 大，或两者距离等于 2。

模型通过嵌入表把编号查成向量。若词表大小为 $V=6$，每个向量宽度为 $d=2$，嵌入表 $E$ 的形状是 `[6,2]`。假设“我”“爱”“数学”三行暂为 `[1,0]`、`[0,1]`、`[1,1]`，三个 token 就变成 `[3,2]` 的矩阵。表里的浮点数是可训练参数；整数编号负责选择行，本身不通过梯度调整。

一批有 $B$ 条、每条 $T$ 个输入 token 时，编号张量是 `[B,T]`，查表后变成 `[B,T,d]`。`B` 数样本，`T` 数位置，`d` 数一个位置的表示分量。把这三个名字写在纸上，比把一串尺寸背下来更可靠。位置向量还会告诉模型“这是第几个位置”，否则仅有相同词的向量不能完整表达顺序。

如果想继续追问“表里的数怎样学出来、为什么有些词向量相似”，读[Embedding 的算法原理与表示学习](chapters/01_Embedding与表示学习.md)：它从重复编号的梯度累加讲到 CBOW、Skip-gram / 负采样和 GloVe，再解释上下文表示、句向量与对比学习。这里先看清编号和向量的区别即可；句向量检索在 Agent 阶段再展开。

## 3. 注意力是在做一次有权重的信息读取

每个位置产生三类向量：查询 $Q$ 表示当前用什么方式匹配其他位置，键 $K$ 用于被匹配，值 $V$ 携带实际被加权的内容。它们通常来自输入表示乘三个可学习矩阵。这里字母 $V$ 又常用于“值矩阵”，和上一节词表大小重名；具体看上下文，本节的 $V$ 是矩阵。

单头计算分三步：先用 $QK^\top$ 得到位置两两之间的匹配分数，再把每行分数经 softmax 变成和为 1 的非负权重，最后按权重混合值。公式为

$$A=\operatorname{softmax}_{\mathrm{每行}}\left(QK^\top/\sqrt{d_k}+M\right),\qquad H=AV.$$

$d_k$ 是一个键向量的宽度；$M$ 是遮住不许读取位置的数值矩阵。权重 $A_{ij}$ 表示第 $i$ 个位置读取第 $j$ 个位置的比例。这里没有预设“名词必然重要”之类规则；匹配方式通过数据训练，注意力图也不能单独作为语义理解或因果解释的证明。

## 4. 三个位置的因果注意力，全部手算

为避免和上一节的二维嵌入混淆，另取一个专用于计算的例子：三个位置的输入为三维单位矩阵 $X=I_3$。选投影后

$$Q=\begin{bmatrix}1\\1\\1\end{bmatrix},\quad
K=\begin{bmatrix}0\\\ln2\\\ln4\end{bmatrix},\quad
V=\begin{bmatrix}2\\4\\8\end{bmatrix}.$$

这些投影可直接由相应列向量作为权重得到。此例 $d_k=1$，缩放因子为 1。因果规则允许每个位置读取自己及更早的位置，禁止读取未来。先加 mask 后，分数矩阵为

$$S=\begin{bmatrix}
0&-\infty&-\infty\\
0&\ln2&-\infty\\
0&\ln2&\ln4
\end{bmatrix}.$$

第一行只有第一个位置有效，指数值为 `[1,0,0]`，权重就是 `[1,0,0]`。第二行指数值是 `[1,2,0]`，除以总和 3，得到 `[1/3,2/3,0]`。第三行指数值是 `[1,2,4]`，除以总和 7，得到 `[1/7,2/7,4/7]`。因此

$$H_1=2,\quad H_2=\tfrac13\times2+\tfrac23\times4=\tfrac{10}{3},\quad
H_3=\tfrac17\times2+\tfrac27\times4+\tfrac47\times8=6.$$

最重要的检查：把第三个位置的值从 8 改成 800，前两个输出应该不变，因为它们看不到未来。若先对未遮挡分数做 softmax，再简单清零未来权重而不重新归一化，第二行权重会是 `[1/7,2/7,0]`，其和不等于 1，已经不是上面的计算。

下面的独立短程序已实跑；它只核对注意力算术，不执行训练。先在项目根目录新建 `study_runs` 文件夹（已有则直接使用），将整个 Python 代码块保存为 `study_runs/attention_first.py`；执行命令在代码后面。

```python
import math
import torch

dtype = torch.float64
q = torch.ones((3, 1), dtype=dtype)
k = torch.tensor([[0.0], [math.log(2)], [math.log(4)]], dtype=dtype)
v = torch.tensor([[2.0], [4.0], [8.0]], dtype=dtype)
future = torch.triu(torch.ones((3, 3), dtype=torch.bool), diagonal=1)
scores = (q @ k.T).masked_fill(future, float("-inf"))
weights = torch.softmax(scores, dim=-1)
output = weights @ v
print(weights)
print(output.squeeze(-1))
expected = torch.tensor([[2.0], [10.0 / 3.0], [6.0]], dtype=dtype)
assert torch.allclose(output, expected)
changed_v = v.clone()
changed_v[2] = 800.0
assert torch.allclose((weights @ changed_v)[:2], output[:2])
assert torch.allclose(weights.sum(-1), torch.ones(3, dtype=dtype))
```

```powershell

```

## 5. 加上批次与多个头，计算含义不变

“多头”让模型在不同投影空间分别进行上述读取，之后合并结果。若 `B=2,T=3,d=4`，分成 `h=2` 个头，则每头宽度 `d_head=2`。常见形状如下：

| 中间对象 | 形状 | 每个轴的意思 |
| --- | --- | --- |
| 输入表示 | `[2,3,4]` | 样本、位置、表示分量 |
| 分头后的 Q/K/V | `[2,2,3,2]` | 样本、头、位置、每头分量 |
| 匹配分数和注意力权重 | `[2,2,3,3]` | 样本、头、读取方位置、被读取位置 |
| 各头读取结果 | `[2,2,3,2]` | 样本、头、位置、每头分量 |
| 合并并投影后的结果 | `[2,3,4]` | 恢复原来的三个轴 |

最后两个位置轴都长为 3，但语义不同，转置错了也可能维度看似合法。较高维点积在简单独立分量假设下会随维度增大方差，除以 $\sqrt{d_k}$ 有助于控制分数尺度；它不是保证训练永远稳定的定理。固定总宽度时增加头数，还会改变每头宽度，不能只数头数判断模型更强。

## 6. “不许看”与“不计分”是两类 mask

Attention mask 决定一个位置能读取谁。因果 mask 遮住未来；padding mask 遮住为了凑齐长度添加的无意义位置。例如一批两条文本分别长 5 与 3，需要补到统一长度时，后者的额外两格不应成为其他位置读取的证据。有效行至少要有一个可读位置，否则全是负无穷的 softmax 可能产生非数值。

Loss mask 决定哪些预测进入平均损失。补齐的目标不计分；做指令微调时，还可能只给助手回答计分，但用户问题仍可以作为回答的上下文。**不计分不等于看不见**：把输入提示从 attention 中遮住，会让模型失去题目。

本项目把无效目标标签设为 `-100`，交给交叉熵忽略。它是损失程序使用的特殊标记，不是词表编号，不能送进 embedding 查表。计算平均值时分母使用有效目标个数，且必须大于零；一批目标全被忽略应单独处理。

## 7. 标签移位后，每个位置到底预测谁

沿用完整序列 `[BOS,我,爱,数学,EOS]`，手动准备：

```text
模型输入：BOS  我   爱    数学
监督标签：我   爱   数学  EOS
```

完整长度为 5，输入和标签长度都为 4。第二个输入位置看到了“我”，监督目标是“爱”；它看到当前位置并未偷看目标，因为目标属于下一格。若批量大小为 `B`，词表有 6 项，此时输出分数 `logits` 形状为 `[B,4,6]`，不是 `[B,5,6]`。

`logits` 是还没归一化的候选分数。对最后一个轴做 softmax 后得到词表概率；正确标签为 $y$ 时，单位置交叉熵是 $-\ln p_y$。若两个有效位置分别给正确词 0.5 与 0.25 的概率，损失分别为 0.693147、1.386294，平均约 1.039721。正确词概率越低，惩罚越大。

训练通常直接把 logits 传给 `cross_entropy`，由函数内部稳定地计算所需归一化，不先手动 softmax 一次再传进去。还要确认模型接口是否内部移位：本仓库脚本在准备输入与标签时移位一次，模型只返回对应位置的 logits；不能再把标签移一次。

## 8. Attention 怎样组成一个可训练模型

本仓库的小模型使用以下顺序：编号查表，加位置向量；先归一化，再做注意力，并把结果加回原表示；再归一化，经前馈网络，又加回原表示；最后归一化并投影到词表分数。

这里残差加法就是 $X+F(X)$，所以两项形状要相同。前馈网络对每个位置单独变换，用相同参数处理各位置；它不会在这一步直接读取其他位置。归一化调整特征的数值尺度；本模型把它放在子模块之前，叫 pre-LN。原始 Transformer 论文包含编码器与解码器，本实验只有用于因果预测的解码器结构，不把两者混为一谈。

所有步骤都是可微运算，最终把有效位置的交叉熵平均成一个标量，就能调用上一课的反向与参数更新。被更新的不只最后词表投影，还包括嵌入、注意力投影和前馈层等参数。生成阶段则把最后位置选出的 token 接回前缀，重复前向；训练位置能并行，不代表依赖前面输出的生成也能一次完成。

### 题 1：注意力输出为什么是值的加权和？

**题目：**三个位置的值分别为 $v_1=2,v_2=4,v_3=15$。给定并固定因果注意力权重：第一行 $[1,0,0]$，第二行 $[1/3,2/3,0]$，第三行 $[1/7,2/7,4/7]$。本题只改变值，不重新计算查询、键或权重。求三个位置输出，并解释第三位置能读哪些值。

<details>
<summary>展开参考答案（先独立作答）</summary>

**参考答案：**输出分别为 $2$、$(2+2\times4)/3=10/3$、$(2+2\times4+4\times15)/7=10$。第三位置读三个值，前两个位置不能读未来的第三值，所以它们的输出不受此次修改影响。

</details>

**面试追问：**修改真实输入 token 时，能总假定注意力权重不变吗？

<details>
<summary>展开追问回答</summary>

**追问回答：**不能。真实 Q/K/V 常由输入共同投影，输入变化会影响值，也可能影响权重。本题明确固定权重，是为了单独核对加权读取。

</details>

### 题 3：padding 为什么不能凭空改善平均 loss？

**题目：**一个 batch 有四个目标位置，其中两个有效位置的负对数损失分别为 1、3，另两个是 padding，loss mask 为 `[1,1,0,0]`。采用有效 token 平均。求正确损失，比较错误地仅把分母设为 4 的结果，并说明增加 padding 应不应该改变指标。

<details>
<summary>展开参考答案（先独立作答）</summary>

**参考答案：**正确损失 `(1+3)/2=2`；只改分母得到 1，虽然有效预测完全没变，指标却变好。按有效位置统计应不因多加无效 padding 改变，分母必须与 mask 对应。

</details>

**面试追问：**如果整个 batch 的 mask 都为零呢？

<details>
<summary>展开追问回答</summary>

**追问回答：**分母为零，不能当作合法零损失。应按预先定义的策略跳过或报错，并记录数据异常。

</details>

### 题 4：取消因果 mask 后 loss 更低，算改进吗？

**题目：**用输入 `[BOS,我,爱,数学]` 预测 `[我,爱,数学,EOS]`。某训练版本允许所有位置相互读取，训练 loss 比因果版本下降更快。请指出至少一个可以偷看的目标，并设计验证这种泄漏的检查，说明部署为什么受影响。

<details>
<summary>展开参考答案（先独立作答）</summary>

**参考答案：**例如 BOS 位置可直接读取后面的“我”，但生成第一个词时没有这个未来输入。应恢复因果可见性，在 eval 模式下只修改未来输入并检查更早 logits 是否保持一致，同时核对标签移位。更低 loss 可能优化了部署无法获得输入的任务。

</details>

**面试追问：**Padding mask 能代替因果 mask 吗？

<details>
<summary>展开追问回答</summary>

**追问回答：**Padding mask 只处理补齐可见性，不禁止读取真实未来 token；两个约束需要按模型接口正确组合。

</details>

如果编号越界，先查是否把忽略标签值当输入；如果 loss 非有限，检查整行注意力被屏蔽与零有效目标；如果续写混乱，检查标签只移位一次，再分开观察首词、方向、后续数字与 EOS。
