第四章按固定预算讨论模型与数据；这一章转向“预算花在哪里”。一次前向可能只激活部分参数，却仍需存储全部参数；生成时还要为历史 token 保存缓存。**MoE** 是让不同 token 选择部分前馈模块的结构，**MLA** 是压缩多头注意力中键值表示的一类方法。读后文每个设计时，先问它改变的是参数存储、实际计算、显存占用还是设备间通信。

先算一个极简账：若有 4 个各含 100 个参数的“专家”，每个 token 只使用其中 1 个，专家总参数是 400，但这次 token 只经过 100 个专家参数。路由和其他网络部分另计。这解释了为什么 MoE 报告要同时给**总参数**与**每 token 激活参数**。MLA 回答另一道账：已生成 token 的键和值要存多少；压缩缓存可能省存储，却仍要付投影与读取的计算。

## 1. MoE：容量与每 token 计算可以不同步增长

在稀疏 MoE 的一个简化层中，router 为 token 选择少数专家：

$$y=\sum_{i\in\operatorname{TopK}(g(x))}w_i(x)E_i(x).$$

总专家参数可能很大，但每个 token 只执行部分专家；因此总参数描述容量和权重存储，激活参数更接近部分计算成本。上式省略共享专家、残差以及具体归一化规则，读报告时必须还原实际架构。

收益的代价包括负载不均、跨设备 token 派发、通信等待和小批次利用率。即使 FLOPs（浮点运算次数）更低，端到端速度也未必更快。路由偏向少数专家可能导致容量浪费；平衡约束过强又可能妨碍内容相关路由。因此要同时看负载统计与任务质量，不能只看专家数。

## 2. MLA：从保存完整 KV 到保存压缩表示

普通多头注意力缓存各头的 key/value。MLA 学习一个低维潜在表示并通过投影形成所需键值，从而减少解码缓存；某些投影可在计算中吸收。其位置处理与内容部分存在专门设计，不应简写为“对 KV 做一次 PCA”。缓存收益也依赖推理实现是否真正使用压缩形式。[DeepSeek-V3 报告](https://arxiv.org/abs/2412.19437v1)

MoE 主要改变前馈容量与计算，MLA 主要针对注意力表示和缓存，两者作用在不同模块。读取 V3 时分别画出 token 经过 attention 与专家层的路径，再问哪些张量必须跨卡、哪些只在本地缓存。

## 3. 显存预算先写清精度和状态

在一种常见混合精度 Adam 配置中，每参数有 2 字节低精度权重、2 字节梯度、4 字节主权重和两个 4 字节动量状态，总计约 $16N$ 字节。这是特定配置下的模型状态估算；不同优化器、dtype、主权重策略会改变系数。还需加激活、临时 buffer、缓存与分配开销。

由此可见，8 GB 显存能装下低精度权重，不意味着能全量训练同等模型。LoRA 减少可训练参数和优化器状态，但前向基础模型、激活与生成缓存仍占空间。激活重计算用额外算力换显存，量化又有误差和算子支持的取舍。

ZeRO 的三阶段逐步分片优化器状态、梯度、参数。理想模型状态可随数据并行设备数下降，但通信和临时聚合并不消失。ZeRO 与 tensor parallel、pipeline parallel 也不是同义词：TP 切算子，PP 切层，普通 DP 复制模型处理不同数据。[ZeRO 省流](../papers/notes/2020_ZeRO.md)

## 6. 深入：路由梯度、潜在缓存与通信

### 6.1 Top-k 到底对什么可导

设 router logits 为 $z\in\mathbb R^E$，本节教学版本先选集合 $S=\operatorname{TopK}(z)$，再在所选集合归一化 $w_i=e^{z_i}/\sum_{j\in S}e^{z_j}$。输出 $y=\sum_{i\in S}w_i E_i(x)$。在没有选择边界变化的局部区域，选中权重是平滑函数；选择集合本身离散，在交换第 k 与 k+1 个专家的边界通常不光滑。

令上游梯度为向量 $g=\partial L/\partial y$，并把专家输出记为 $e_i$，则所选 logits 的局部梯度为

$$\frac{\partial L}{\partial z_i}=w_i\,g^\top(e_i-y),\quad i\in S.$$

该教学版本中未选 logits 对当前任务输出的局部梯度为零。如果先对**全部**专家 softmax，再取 top-k 而不重新归一化，未选 logits 仍通过分母影响所选权重；两种算法不能混写。共享专家、sigmoid 评分、路由偏置等实际变体也需回到报告或代码的定义。

负载平衡不是只有一种 loss。例如 top-1 教学代理 $L_{bal}=E\sum_i f_i p_i$，其中 $f_i$ 是硬派发比例（此处 stop-gradient），$p_i$ 是批内平均全专家 softmax 概率。它鼓励降低过载专家的概率，但其梯度与任务梯度可能冲突；不能凭 loss 下降判定质量提升。V3 的选择偏置不直接作为输出权重，且仍有补充的序列级辅助项，故“auxiliary-loss-free”不能解释为模型从来没有任何辅助 loss。[V3 路由定义](https://arxiv.org/html/2412.19437v1#S2.SS1.SSS2)

容量系数可按每专家约 $\lceil c\,T k/E\rceil$ 个 token 槽估算，$T$ 是批内 token 数。超容量时丢弃、重路由或动态扩容会改变计算与训练；现代实现也可不丢 token。至少记录每专家计数、最大/均值、未派发数、通信时间和有效吞吐。

### 6.2 MLA 的矩阵吸收为何成立

用单层、单头的教学记号：$h_t\in\mathbb R^d$，缓存潜变量 $c_t=W_Dh_t\in\mathbb R^{d_c}$；内容键 $k_t^C=U_Kc_t\in\mathbb R^{d_k}$，值 $v_t=U_Vc_t\in\mathbb R^{d_v}$。查询 $q^C\in\mathbb R^{d_k}$，则

$$ (q^C)^\top k_t^C=(U_K^\top q^C)^\top c_t,\qquad
\sum_t a_t v_t=U_V\left(\sum_t a_t c_t\right).$$

所以内容分数可在潜在维度计算，先对潜变量聚合再上投影。等式要求投影是线性的、矩阵固定，并正确处理 softmax 的总分数缩放；它证明计算等价，不证明压缩架构与任意原始 MHA 模型等价。训练本来就在该受约束表示空间中学习。

若对内容键逐位置应用 RoPE，分数含 $q^\top R_t U_Kc_t$，位置相关的 $R_t$ 使投影无法统一吸收到一个与 t 无关的查询。解耦设计把内容分数与旋转位置分数相加：$s_t=((q^C)^\top k_t^C+(q^R)^\top k_t^R)/\sqrt{d_k+d_R}$；缓存 $c_t$ 和已按自身位置旋转的 $k_t^R$，后者可跨头共享。此处概括核心线性关系，具体查询压缩和输出投影见 [V2 的 MLA](https://arxiv.org/html/2405.04434v5#S2.SS1)。

普通 MHA 的 KV 缓存约 $2BLTHd_hs$ 字节，潜变量加共享位置键约 $BLT(d_c+d_R)s$。这是指定布局的缓存账，GQA 的基线应改用 KV 头数，不能继续使用查询头数。

教学配置 $B=2,L=4,T=100,H=8,d_h=64,s=2,d_c=128,d_R=32$：完整 KV 为 1,638,400 字节，潜在缓存 256,000 字节，相差 6.4 倍。该例用键的内容 32 维、旋转 32 维与值 64 维，不是 V3 的正式配置；只改变纸面公式而运行时仍保存上投影 KV，实际不会得到这项节省。

### 6.3 画出 TP、PP 与专家并行的张量路径

以 $Y=XW_1W_2$ 为线性教学块，把 $W_1$ 按输出列分成 $W_{1,a},W_{1,b}$，每卡先算本地中间激活；把 $W_2$ 按对应输入行分成 $W_{2,a},W_{2,b}$，得到两个输出贡献并相加。列并行第一层可以保持中间结果分片，行并行第二层常需归约。加入逐元素激活仍可本地处理；LayerNorm 等跨特征操作则要另外分析依赖。

PP 把层分到阶段，用微批交错减少空闲。在各阶段时间相同、无通信等理想假设下，简单填充/排空流水线的利用率约 $m/(m+p-1)$，$m$ 是微批数，$p$ 是阶段数。真实调度、前后向不对称和通信都会改变它；增加 m 也会增加调度或激活压力，不能无条件说越大越好。

专家并行把专家分到设备。一次派发把 token 隐状态送到专家，合并把专家输出送回来；若 T 个 token 各选 k 个**远端**专家、隐藏维 d、每元素 s 字节，单次前向的逻辑载荷粗估为 $2T k d s$。本地派发不走网络，反向还要另计；这个值不是每卡实际线速流量，也没包含索引、路由权重、拓扑与重复传输。训练 DP 的梯度通信、TP 的激活通信、专家派发通信有不同发生频率。

### 6.4 低精度与显存优化怎样做对照

量化教学式 $\hat x=\Delta\,\operatorname{clip}(\operatorname{round}(x/\Delta),q_{min},q_{max})$ 把舍入误差和饱和误差分开。无饱和时误差至多 $\Delta/2$；离群值会迫使全张量 scale 变粗，分块 scale 改善局部分辨率但增加元数据和算子复杂度。FP8 是浮点格式，不能直接套整数格式的等距误差结论。

验收顺序为：与较高精度比较同输入前向和梯度，观察误差分布与离群位置，再跑小训练比较收敛，最后测端到端吞吐和峰值。激活重计算会减少保留激活并重做前向；若重计算的 dropout 随机状态或状态性模块不同，可能改变梯度。资源报告把权重/优化器、激活、临时 buffer、KV 和通信分别列出，不能把 $16N$ 当成所有显存。
