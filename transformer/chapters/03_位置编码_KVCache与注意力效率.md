**本章问题：同一个 attention 公式，为什么训练、长提示和逐 token 生成的瓶颈不同？** 先掌握上一章的因果预测，不必先学 GPU 内核。

上一章训练时一次看完整句子的各个位置；真正续写时，却要先输入已有文字，再一次生成一个新 token。模型需要知道“小猫”与“毛线”的先后顺序，因而要引入位置信息；生成新 token 时又会重复读取旧 token，因而希望缓存已算过的键和值。下面先分别定义**位置表示**与 **KV cache**，再比较它们节省或增加哪类成本。

先把缓存想成一张随生成增长的表：提示有 3 个 token，就先存 3 行键和值；生成第 4 个 token 时，只新增第 4 行，再让当前位置读取前 4 行。**prefill** 是处理已有提示并建立这张表，**decode** 是之后逐个生成。缓存减少重复计算，却要为表本身付显存。下面的大公式只是把“表有多少层、多少头、多少行、每项多少字节”相乘。

## 1. 顺序从哪里进入模型

没有位置或其他顺序信号的全连接 self-attention 对输入排列具有等变性。因果 mask 引入可见范围的顺序约束，但它不替代所有位置建模。原 Transformer 把正弦位置向量加到 token embedding；学习式绝对位置表则给每个位置一个可训练向量，超出表长需要另行处理。

RoPE 对 query/key 的二维子空间做旋转。设位置 $m$ 的旋转为 $R_m$，则

$$\widetilde q_m=R_mq_m,\quad\widetilde k_n=R_nk_n,\quad
\widetilde q_m^\top\widetilde k_n=q_m^\top R_{n-m}k_n.$$

最后一步来自同一二维频率下旋转矩阵的群性质；完整向量使用多个频率组成块对角旋转。因此点积显式包含相对位移，而内容仍由 $q,k$ 决定。这个恒等式不意味着模型已学会任意长上下文；训练长度、频率分布和位置缩放都会影响外推。[RoFormer 原文](https://arxiv.org/abs/2104.09864)

## 2. Prefill 与 decode

Prefill 对已有长度 $T$ 的提示并行计算隐藏状态，并保存各层 key/value。生成一个新 token 时，其 query 只需读取已有缓存和自己的 key/value，不必重新前向整个前缀。位置编号、mask 与缓存内容必须一致，否则缓存版结果可能与完整重算不一致。

忽略其他工作，一次完整长度 $T$ 的注意力约为 $O(T^2d)$；已有缓存的一个生成步约为 $O(Td)$，但从短序列生成至长序列仍累计二次级别的读缓存工作。缓存减少重复计算，并没有让完整自回归生成变成常数成本。

普通缓存的字节数近似为

$$M_{KV}=2BLTH_{KV}d_hs,$$

其中 2 代表 key 与 value，$L$ 是层数，$H_{KV}$ 是 KV 头数，$s$ 是每元素字节数。例如 $B=1,L=24,T=4096,H_{KV}=8,d_h=64,s=2$ 时，约为 192 MiB；这还没有包含模型权重、激活和分配器开销。服务中的并发请求数直接放大这项成本。

## 3. 不同优化改的是不同成本

MQA 让多个 query 头共享一个 KV 头，GQA 在每组 query 头之间共享 KV，因此减小缓存和读取量，但改变了表示结构。FlashAttention 的主要思想则是分块计算、在线 softmax 与减少昂贵显存读写，在数值误差范围内计算相同的精确 attention；它不是把稠密 attention 的理论计算量变成线性。[FlashAttention](https://arxiv.org/abs/2205.14135)

滑动窗口限制可见位置，会改变模型可以利用的信息；低精度 KV 会引入量化误差；分页缓存主要改善分配与利用率。这些方法可组合，但评测应分别记录精度、上下文范围、吞吐、延迟与峰值显存。

训练主要关注前向和反向及激活保存，生成还受缓存、批次和内存带宽影响。某种内核让长序列训练更快，不意味着低并发逐 token 延迟按同样比例改善。评测时必须写出硬件、dtype、batch、输入长度、输出长度和预热规则。

## 4. 用等价性检查发现实现问题

最有价值的小实验是比较完整重算与缓存逐步计算的 logits；使用 eval 模式、同一位置编号和容差。再把位置偏移故意加 1，确认检查能发现错误。若实现 RoPE，还应数值检查旋转前后向量范数保持，以及上述相对位移等式。

## 5. 深入：RoPE、缓存位置与在线 softmax

### 把旋转写成逐分量运算

在一个二维子空间定义

$$
R(\theta)=\begin{bmatrix}\cos\theta&-\sin\theta\\\sin\theta&\cos\theta\end{bmatrix},
\qquad R(\theta)^\top R(\phi)=R(\phi-\theta).
$$

若 $d_{rot}$ 个维度参与旋转且为偶数，可按相邻两维配对，第 j 对频率为 $\omega_j=b^{-2j/d_{rot}}$，$b>1$ 为频率基底。位置 m 施加角度 $m\omega_j$。以 x 的一对分量 a、c 为例，输出是 `[a cos(mω)-c sin(mω), a sin(mω)+c cos(mω)]`。完整变换是这些小矩阵的块对角组合。[RoFormer 方法](https://arxiv.org/abs/2104.09864)

这给出相对位移恒等式，但不仅依赖“有 sin/cos”：Q 与 K 必须使用兼容频率、位置和分量配对。某些实现用前后半维配对，某些用相邻维；两者可以通过相应权重布局转换表达，但不能在一个已训练检查点中随意交换。缓存一般保存已经按**各 key 自己的位置**旋转的 K；新 query 只用新位置旋转，不能把全部旧 K 重新按当前位置旋转。

### 缓存等价性来自因果信息流

在确定性因果模型中，历史位置的表示仅依赖当时前缀；追加一个新 token 不会改变这些历史表示。因此各层历史 K/V 可复用，新 token 在每层计算自己的 Q/K/V，读取已有历史。这个论证要求同一权重、位置机制、有效可见范围和模块状态；训练 Dropout、改变位置编号或非因果跨位置运算都会破坏直接比较条件。

设已有 p 个有效缓存位置，新块长度为 u，新 query 第 i 行（从 0 起）最多可见 key 索引 $p+i$，因此矩形因果 mask 是 $j\le p+i$。不能对 `[u,p+u]` 简单套以左上角为基准的 `tril()`：当 u=1、p>0 时，错误 mask 可能只允许第一个历史 key。批内长度不同还需按每条样本的 cache length 与 position IDs 处理。

缓存检查至少覆盖：一次追加一个 token、一次追加多 token、不同前缀长度、右 padding 和 batch；比较每个有效新位置的 logits，不只看 argmax。浮点误差容差与 dtype、归约长度有关，不能要求所有设备都逐位相同。

### 在线 softmax 为什么能合并分块

对一个固定 query，已处理分数集合维护最大值 m、指数和 l、带 value 的分子向量 a：

$$
l=\sum_j e^{s_j-m},\qquad a=\sum_j e^{s_j-m}v_j,\qquad o=a/l.
$$

加入一块 B，令 $m'=\max(m,\max_{j\in B}s_j)$。旧块的尺度从 $e^{s-m}$ 变成 $e^{s-m'}$，故

$$
l'=e^{m-m'}l+\sum_{j\in B}e^{s_j-m'},
\qquad
a'=e^{m-m'}a+\sum_{j\in B}e^{s_j-m'}v_j.
$$

两项恰好恢复所有已见位置在共同尺度下的指数和，最终 a/l 与一次性 softmax 相同。第一块可直接初始化 m/l/a；全被屏蔽的块应跳过，整个 query 无可见 key 则按契约处理。该合并在实数算术中精确，浮点合并顺序会产生容差内差异。

FlashAttention 把这一思想与硬件分块、片上存储和反向重算结合，减少显存读写和完整中间矩阵存储。这里证明的是在线归一化，不等于手写 Python 循环已有 FlashAttention 的速度；Q/K 配对仍然存在，理论稠密计算量仍有二次项。[FlashAttention 原文](https://arxiv.org/html/2205.14135v1)

取 scores=`[0,ln2,ln4]`、values=`[1,3,5]`，权重为 `[1/7,2/7,4/7]`，输出 $27/7$。先处理前两个再处理第三个，使用上述缩放可得到同一输出；给所有分数加 1000 也应保持结果，用稳定指数实现避免溢出。这是在线 softmax 的最小实现作业。

### 推理优化需要同时看三类时间

首 token 延迟主要含排队和 prefill；每个后续 token 的间隔反映 decode；吞吐统计固定负载下每秒有效生成 token。增加 batch 可能改善吞吐，却增加排队或单请求延迟。KV 压缩可能降低带宽与容量需求，但量化、重建和投影也要计算；实际收益应在相同上下文和质量下测量。

读缓存的工作量随上下文增大，但权重读取、FFN 与投影仍存在。缓存 O(T) 的存储、单步 O(T) 的注意力，与整段生成累计 O(T²) 的配对工作是不同口径。分页或前缀复用改变分配与重复读取，不会自动改变模型可见的信息或语义质量。

## 6. 完整自测与面试问答

### 题 1：KV Cache 保存什么，怎样估算显存？

**题目：**采用普通未量化 KV Cache，批大小 B=2、层数 L=16、已缓存长度 T=512、每层 KV 头数 $n_{kv}=4$、每头维度 $d_h=64$，每元素 2 字节。只计 K 与 V，缓存字节数为 $2BLTn_{kv}d_h\times2$。计算 MiB（$1\,\mathrm{MiB}=2^{20}$ 字节），再把 KV 头数改为 16 比较。

<details>
<summary>展开参考答案（先独立作答）</summary>

**参考答案：**四个 KV 头时为 16,777,216 字节，即 16 MiB；16 个 KV 头时为 64 MiB。缓存历史各层的键和值，后续新 token 只需计算自己的 Q/K/V 并读取历史，节省前缀重算。实际还需权重、其他激活与分配开销。

</details>

**面试追问：**为什么通常不需要长期缓存历史 Q？

<details>
<summary>展开追问回答</summary>

**追问回答：**生成新位置主要使用该新位置的 query，与历史 K 匹配并读取历史 V；旧位置的 query 不再用于当前输出。

</details>

### 题 2：RoPE 为什么能在点积中体现相对位置？

**题目：**二维旋转 $R(\alpha)$ 满足 $R(\alpha)^\top R(\beta)=R(\beta-\alpha)$。一个二维子空间里 $q=k=(1,0)^\top$；位置 m、n 分别施加旋转 $R(m\omega),R(n\omega)$，$\omega$ 是固定频率。求旋转后内积并说明依赖的位置信息。

<details>
<summary>展开参考答案（先独立作答）</summary>

**参考答案：**内积为 $q^\top R(m\omega)^\top R(n\omega)k=q^\top R((n-m)\omega)k=\cos((n-m)\omega)$，旋转保持向量范数，并让该点积依赖相对位移 n-m。真实 RoPE 在多个二维子空间使用不同频率。

</details>

**面试追问：**加入 RoPE 就保证任意长上下文外推吗？

<details>
<summary>展开追问回答</summary>

**追问回答：**不能。训练位置范围、频率与缩放、数据和实现都会影响外推，必须在目标长度下评测，并检查缓存的位置编号是否一致。

</details>

### 题 3：MHA、MQA、GQA 与 FlashAttention 各改变什么？

**题目：**面试官问这四种注意力相关设计为什么能改善推理或训练成本。请说明多头注意力 MHA、多查询 MQA、分组查询 GQA 的 KV 共享差异，以及 FlashAttention 是否把精确稠密注意力的计算量变成随长度线性增长。

<details>
<summary>展开参考答案（先独立作答）</summary>

**参考答案：**MHA 通常各查询头有自己的 KV；MQA 让多个查询头共享一组 KV；GQA 每组查询头共享 KV，减少缓存和读取量。FlashAttention 通过分块、在线 softmax 和减少显存读写来计算精确注意力，避免存储完整注意力矩阵的某些开销；精确稠密注意力的配对计算量仍随长度平方增长。

</details>

**面试追问：**怎样验证 KV Cache 实现正确？

<details>
<summary>展开追问回答</summary>

**追问回答：**在 eval 模式、相同参数、输入和位置编号下，比较全前缀重算与逐步缓存的 logits，并使用合适容差；分别检查长度增长、批次与 EOS 边界。

</details>

<details>

### 题 6：实现分块 softmax 并证明合并

**题目：**scores=`[0,ln2,ln4]`，values=`[1,3,5]`，全部可见。用 m/l/a 状态实现分块读取，分别采用块大小 1、2、3，返回加权输出。推导加入一块时的缩放因子，说明给所有 scores 加 1000 后如何避免溢出；不要求实现 GPU 内核。

<details>
<summary>展开参考答案（先独立作答）</summary>

**参考答案：**共同尺度由新最大值 m' 决定，旧 l/a 乘 `exp(m-m')`，新块累加 `exp(s-m')` 及其 value 加权和。三种划块输出均为 $27/7\approx3.857142857$，大共同偏移不改变结果。测试空可见集的约定，并用全量稳定 softmax 作为独立参照。

</details>

**面试追问：**这个函数通过，是否就证明 FlashAttention 的吞吐？
