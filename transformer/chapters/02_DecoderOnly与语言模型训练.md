# 第 2 章：Decoder-only 与一次完整语言模型训练

**本章问题：文本怎样变成一个能反向传播的标量？** 前置是上一章 attention 与框架中的自动微分。预训练和 SFT 经常复用相同的 next-token 计算，但数据分布、监督区间和训练目的不同。

沿用上一章的三词句“小猫 / 追逐 / 毛线”：若给模型“小猫”，训练目标可设为“追逐”；给它“小猫 追逐”，目标可设为“毛线”。把每个位置都用于预测下一个 token，得到语言模型训练样本。**Decoder-only** 指只使用因果读取前文的生成网络；本章先把输入与标签对齐，再把各位置的预测误差汇成一个损失。

## 1. 从联合分布到交叉熵

对 token 序列 $x_{1:T}$，概率链式法则给出

$$p_\theta(x_{1:T})=\prod_{t=1}^T p_\theta(x_t\mid x_{<t}).$$

Decoder-only 用因果 self-attention 建模条件分布。它不需要原始翻译架构中的独立 encoder 和 cross-attention。输出隐藏状态经词表投影得到 logits `[B,T,V]`，softmax 后是每个位置上的词表分布。这里的“decoder”描述因果生成结构，不意味着必须有一个配套 encoder。

训练通常输入 `tokens[:, :-1]`，标签为 `tokens[:, 1:]`。例如输入 `[BOS,我,喜欢]`，标签为 `[我,喜欢,数学]`；若又让框架内部移位一次，就会变成预测隔一个 token 的错误任务。先确认模型 API 是否自带 shift，再决定由哪一层负责。

若原始 token 张量长度为 $T$，手动移位后的输入和标签长度为 $T-1$，相应 logits 是 `[B,T-1,V]`；前面的 `[B,T,V]` 是以实际模型输入长度记号描述。实现中应直接检查两个位置轴一致。

带监督 mask $m_{bt}\in\{0,1\}$ 的损失为

$$\mathcal L=-\frac{\sum_{b,t}m_{bt}\log p_\theta(y_{bt}\mid x_{b,\le t})}{\sum_{b,t}m_{bt}}.$$

分母必须与目标一致。按有效 token 平均与先对每条样本平均再取平均，会赋予长短样本不同权重。梯度累积时，如果微批次有效 token 数不同，简单平均每个微批次的 mean loss 也未必等价于一个大批次的 token 平均。

还必须要求 $\sum m_{bt}>0$。回答被截断后可能没有任何监督 token，应记录原因并拒绝或跳过该批次，不能让除零得到的 NaN 继续参与更新。

## 2. 数据边界先于网络深度

Tokenizer 定义词表和文本切分，它不是可以忽略的预处理。比较 perplexity $\exp(\mathcal L)$ 时，应固定分词器、数据、监督区间和 loss 归一化；不同 token 粒度下的困惑度不能直接当作能力排名。

先按文档、来源或问题实体切分，再构造训练窗口。若先滑窗后随机分配，几乎相同的片段可能跨训练与测试。packing 提高利用率，但需要决定文档间是否允许 attention、位置如何计数、EOS 是否纳入监督。把不相干文本拼在一起而不记录规则，会让“相同数据量”失去明确含义。

SFT 常把用户问题放进上下文，只对助手回答计算 loss。被 mask 的 prompt 仍参与前向并影响回答；“不对该 token 直接算交叉熵”不等于“其表示和共享参数没有梯度贡献”。DPO 还需要把回答 token 的 log-prob 求和，衔接 [后训练第 1 章](../../post_train/chapters/01_语言模型到后训练.md)。

## 3. 训练循环的可检查对象

一轮更新依次是取批次、清梯度、前向、计算损失、反向、必要时裁剪梯度、优化器更新。混合精度、学习率调度和累积会增加状态，应在最简单循环正确后逐项加入。AdamW 的权重衰减与把 L2 项加入自适应优化目标并非一般等价。

验证必须切到 eval 模式并关闭梯度记录，报告所有有效验证 token 的总负对数似然除以总数，而不是对长度不同的 batch loss 不加权平均。保存要区分“只供推理的权重”和“能精确续训的检查点”：后者还需优化器、调度器、随机状态与数据迭代位置。

loss 下降只表明当前目标被优化。先用极小数据集检查能否过拟合，再看独立验证曲线。如果训练 loss 不降，先查标签、mask、梯度、学习率；如果训练降而验证升，查容量、数据量、切分与正则，不能直接归咎于模型结构。

## 4. 本章实验与边界

[教学脚本](../experiments/README.md) 用可解释的数字序列语法训练一个小型因果 LM，并检查未来信息屏蔽、标签和重载一致性。它验证真实张量与反向传播，但没有自然语言理解、真实 tokenizer 或通用推理能力；同一语法中的长度切分也不是严格的领域外泛化。

验收时手动抽一条样本，列出输入、标签、有效 mask、每个 token 的负 log-prob。然后改变归一化方式，预测长样本相对权重如何变化。完成后再进入 [SFT](../../post_train/chapters/02_SFT_数据与参数高效微调.md)。

参考：[D2L 语言模型章节](https://d2l.ai/chapter_recurrent-neural-networks/language-model.html)、[GPT-3 原文](https://arxiv.org/abs/2005.14165)、[PyTorch CrossEntropyLoss](https://docs.pytorch.org/docs/stable/generated/torch.nn.CrossEntropyLoss.html)。

## 5. 深入：从概率目标到一段可核对的实现

### 最大似然为什么得到交叉熵

设真实条件分布为 $p_*(y\mid s)$，模型为 $p_\theta(y\mid s)$，在固定状态 s 下的期望负 log-prob 为

$$
\mathbb E_{y\sim p_*}[-\log p_\theta(y\mid s)]
=H(p_*(\cdot\mid s))+D_{KL}(p_*\|p_\theta).
$$

其中 H 是真实分布的熵，KL 在真实分布有质量而模型为零处为无穷。H 不依赖参数，所以最小化交叉熵等价于在模型可表示范围内减少该方向 KL。真实分布不确定时，最优 loss 也大于零；模型容量、有限数据和优化又可能带来额外差距。这个恒等式解释训练目标，不能将平均 NLL 直接解释为每次回答正确率。

训练时 teacher forcing 提供真实前缀，因果网络并行计算每个条件分布。生成时前缀来自模型自身，错误可能改变之后的状态分布。标签移位与因果 mask 保证训练条件合法，却不消除这种分布差异。

### 写出 token log-prob 的轴与边界

下面输入完整 token IDs `[B,L]`、同长度模型 logits `[B,L,V]` 和目标位置 mask `[B,L]`；mask 标记“这个编号是否作为预测目标”。IDs 必须全部在词表范围内，ignore 值不能直接拿来 gather。函数手动移位一次，模型前向本身不额外计算 loss。

```python
import torch

def next_token_stats(logits, ids, target_mask):
    if logits.shape[:2] != ids.shape or ids.shape != target_mask.shape:
        raise ValueError("logits、IDs 和目标 mask 的位置轴不一致")
    logp = logits[:, :-1, :].log_softmax(dim=-1)
    targets = ids[:, 1:]
    valid = target_mask[:, 1:].bool()
    counts = valid.sum(dim=-1)
    if (counts == 0).any():
        raise ValueError("至少一条样本没有有效监督目标")
    token_logp = logp.gather(-1, targets.unsqueeze(-1)).squeeze(-1)
    sequence_logp = torch.where(valid, token_logp, 0.0).sum(dim=-1)
    token_mean_loss = -sequence_logp.sum() / counts.sum()
    return token_mean_loss, sequence_logp, counts
```

同一函数同时给出全批 token 平均 loss 和每条序列的 log-prob **和**，二者服务不同用途。有效 token 求和对应训练归约；DPO 需要回答区间的序列和。混合精度下需按实现用稳定精度做 log-softmax 与归约；验证则累积 NLL 总和和有效数，不累积 batch 均值。

### Tokenizer、EOS 与概率单位

BPE 从初始符号序列出发，按语料中的相邻符号统计逐步合并常见对，得到可复用的子词词表；训练分词器和用固定分词器编码是两个步骤。byte、字符、子词的粒度改变词表、序列长度和 loss 的计量单位。不能用不同 tokenizer 的 perplexity 直接给模型能力排序。[BPE 原论文](https://aclanthology.org/P16-1162/)

对固定字符串，若两个编码的整段概率都为 1/16，一端是 4 个目标 token，另一端是 2 个，则 token 均值 NLL 分别为 $\ln2$、$\ln4$，perplexity 分别为 2、4。这没有改变该字符串的整段概率。按字节或字符归一化可以提供另一种比较口径，但仍要固定字符串集与概率计算边界。

EOS 定义终止行为。训练只监督正文而漏掉 EOS，模型可能学到内容却不会按任务要求停止；训练和评测对 EOS、截断和最大长度的约定必须一致。padding 与 EOS 也要分别处理，即使某模型使用同一 token ID，通过 attention/loss mask 仍需区分实际用途。

### 从单批次核对到预训练实验

先验证函数和因果性，再训练单条确定序列，之后恢复多样数据与独立切分。日志应能重建有效训练量：updates、seen_tokens、learning_rate、train_nll、val_nll、gradient_norm。数据顺序和学习率调度同时变化会产生混杂，预算对照要固定所研究变量之外的处理。

语言模型可产生概率，不等于遵循指令。进入 SFT 后通常复用同一网络和 next-token 计算，主要改变数据与监督范围；进入 DPO/RL 后再改变反馈和目标。理解这一复用关系，才能解释一个后训练实现到底更新了什么。

## 6. 完整自测与面试问答

### 题 1：next-token loss 怎样对应到输入和标签？

**题目：**一批两条完整序列补齐后的 token IDs 形状为 `[2,5]`，词表大小 13。程序在外部把输入取前四项、标签取后四项，模型不在内部移位。写出输入、标签与 logits 形状，说明 logits 最后一维及 padding label 的处理。

**参考答案：**输入与标签均为 `[2,4]`，logits 为 `[2,4,13]`。每个位置的 13 个数是下一 token 各候选的分数；每个有效目标是一个整数编号。补齐目标按 loss mask 或忽略索引排除，并用有效目标数作所选 token 均值的分母。

**面试追问：**Decoder-only、encoder-only 与 encoder–decoder 用途怎样区分？

**追问回答：**Decoder-only 用因果前缀生成后续；encoder-only 通常读取完整输入以提取表示；encoder–decoder 由源端编码、目标端因果生成并交叉读取源端。具体任务与监督目标仍需明确，不能仅由结构名推断能力。

### 题 2：验证集为什么不能直接平均 batch loss？

**题目：**验证被划为两个 batch，分别有 8 与 2 个有效 token，各自 token 平均 loss 为 1 与 3。没有参数更新。计算全验证集 token 均值，以及错误的 batch 均值；若重新分批，哪一个统计量应保持一致？

**参考答案：**全数据 token 均值为 `(8×1+2×3)/10=1.4`；不加权 batch 平均为 `(1+3)/2=2`。应汇总损失总和与有效数后相除，数值容差内不应因验证分批方式改变。

**面试追问：**为什么语言模型 loss 不能总要求接近零？

**追问回答：**若同一前缀存在多个合法续写，真实条件分布有不确定性；合理模型仍有正损失。还要分开检查确定性目标、EOS 规则与标签错误。

### 题 3：小数据过拟合测试能诊断什么？

**题目：**一个因果 LM 在正常数据上训练 loss 不下降。你固定一条完整且标签确定的序列，关闭随机数据变化，在同一小样本上训练。请说明应检查的输入、标签、梯度与更新，以及通过该测试后还需要验证什么。

**参考答案：**打印一次移位、有效 mask、目标编号和每位置 loss，确认 loss 连到模型参数、梯度非零且优化器包含这些参数，再用合适学习率看固定样本 loss 是否下降。它有助于定位实现或优化问题；通过后仍需独立数据的验证、正常数据训练稳定性与生成测试。

**面试追问：**训练 loss 低、验证 loss 升高通常查什么？

**追问回答：**检查过拟合、数据划分与分布差异、样本数量、正则和配置选择；不能只凭这两条曲线把原因定为某个模块。

### 题 4：手写有效 token loss 与序列 log-prob

**题目：**完整 IDs=`[[0,1,2]]`，0 为 BOS、2 为 EOS，目标 mask=`[[0,1,1]]`。第 0 位置下一 token 概率 `[0.25,0.5,0.25]`，第 1 位置为 `[0.1,0.2,0.7]`，第 2 位置输出不参与监督。写出有效目标、序列 log-prob 和 token 平均 loss，实现本章接口，并加入 padding 和零有效目标检查。

**参考答案：**有效目标为 1 与 2，对应概率 0.5 与 0.7，序列 log-prob 为 $\ln0.35\approx-1.049822124$，均值 loss 约 0.524911062。用 log-softmax 与 gather 取目标轴，再按移位后的 mask 求和。追加补齐位置且保持原有效状态时结果应一致，零有效样本按契约拒绝；另外对照标准交叉熵的相同归约。

**面试追问：**第一份回答 token 应读哪个位置的 logits？

**追问回答：**最后一个 prompt 输入位置的 logits，因为该位置预测紧随其后的第一回答 token；若取回答自己位置就整体错位。

### 题 5：交叉熵凸，为什么模型训练仍有困难？

**题目：**固定状态下真实分布 p 为 `[0.5,0.5]`，模型分布 q 为 `[0.8,0.2]`。用自然对数计算交叉熵、H(p) 与 KL(p||q)，核对三者关系。说明 logits 上的凸性为什么不证明 Transformer 参数目标凸。

**参考答案：**交叉熵为 $-0.5\ln0.8-0.5\ln0.2\approx0.916290732$；H(p)≈0.693147181；KL≈0.223143551，相加一致。logits 对参数是多层非线性映射，凸函数与一般非线性映射复合不保持凸性，训练还受优化、数据和容量影响。

**面试追问：**真实分布不确定时 loss=0 是否是合理验收？

**追问回答：**不是一般合理目标。交叉熵下界包含真实条件熵；确定单序列的过拟合诊断与真实多样数据的泛化评测应分开。

### 题 6：如何排查窗口切分造成的验证泄漏？

**题目：**一个长文档先切成长度 100、步长 1 的重叠窗口，再把窗口随机按 9:1 分成训练/验证。模型验证 loss 极低。给出相邻窗口共有 token 数，设计一种能检验泄漏的重新划分和对照；必须说明 tokenizer 与训练预算如何控制。

**参考答案：**相邻窗口共有 99 个 token，几乎同一内容可落在两边。先按源文档或近重复族划分，再在各自集合内构窗；固定 tokenizer、模型、有效训练 token 和评测口径，比较原切分、隔离切分及逐来源结果。验证变难说明原指标过于乐观的一种证据，仍需控制来源分布和训练量，不能只凭升高就量化全部污染贡献。

**面试追问：**去掉完全相同窗口就够了吗？

**追问回答：**不够。大量近重复、同题变体和同源片段仍可共享答案信息，应按文档、问题族或近重复簇处理并抽查。
