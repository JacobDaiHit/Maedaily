# 实验 A1：真正训练一个微型因果语言模型

这个实验把 token、因果注意力、位置嵌入、交叉熵、反向传播和生成连起来。模型在 CPU 上学习数字按模 10 递增或递减的语法，真实更新 14,112 个参数；没有调用大模型 API、下载预训练权重或安装依赖。

它是 [GOAL 项目 A](../../GOAL.md) 的初步实验：已经包含小模型训练、验证、检查点往返和学习率对照；尚未覆盖 GPU 显存/吞吐、独立多种子结论、自然语言数据与完整项目报告。因此不把本实验通过称为项目 A 全部验收完成。

## 运行方式与环境

在仓库根目录 PowerShell 中执行本机已验证的解释器：

```powershell
& 'D:\anaconda\envs\pytorch_env\python.exe' transformer/experiments/tiny_causal_lm.py
```

本次实际环境：Python 3.11.15、PyTorch 2.7.1+cu118。即使环境能检测到 CUDA，脚本也显式使用 CPU、1 个计算线程和 1 个 interop 线程，并启用确定性算法。运行无需额外环境配置。

默认 seed=7、每组 200 步、batch size=16，比较学习率 0.001 与 0.003。输出位于 [results/summary.json](results/summary.json) 和 [results/learning_curve.csv](results/learning_curve.csv)，重复执行会覆盖同名结果。保留另一组结果时指定独立目录：

```powershell
& 'D:\anaconda\envs\pytorch_env\python.exe' transformer/experiments/tiny_causal_lm.py --seed 11 --output-dir transformer/experiments/results_seed11
```

脚本会临时保存并重载一个小检查点，核对完成后自动移除；不留下权重文件。换设备或软件版本不保证逐位一致，应重新运行数值检查。

## 数据：留出完整长度，不制造“领域外泛化”结论

词表含 `<PAD>`、`<BOS>`、`<EOS>` 与 0–9，共 13 个 token。每条完整序列为 BOS、若干数字、EOS；方向为 +1 或 −1，数字按模 10 循环。例如：

```text
<BOS> 7 8 9 0 1 2 <EOS>
<BOS> 2 1 0 9 8 7 <EOS>
```

训练集数字长度为 6、8、10，每个长度枚举 10 个起点和 2 个方向，共 60 条。验证集长度为 7、9，同样枚举起点与方向，共 40 条。完整序列和长度集合不重叠；切分发生在生成完整序列之后，不把同一条序列的前半段当训练、后半段当验证。

这仍是共享语法、共享数字和部分共享前缀的长度插值测试。验证长度位于训练范围内，位置嵌入不会因为验证长度而访问训练从未覆盖的高位置。不能据此声称领域外推理或任意长度外推。

此外，给定 BOS 时起始数字未知，给定首个数字时方向未知，结束长度也没有作为条件给出；因此部分目标有内在不确定性。模型倾向训练中出现过的 EOS 位置也可能影响验证损失。不要要求整套数据交叉熵降为零，也不要只凭一条生成判断是否学会语法。

## 模型与张量

[tiny_causal_lm.py](tiny_causal_lm.py) 自写单层 pre-LN 模型：token embedding + 学习式 position embedding → LN → 双头因果 attention → 残差 → LN → 四倍宽 MLP/GELU → 残差 → final LN →词表线性层。隐藏维度 32、2 个头，每头 16；上下文容量 16；没有 dropout。模型没有使用 `nn.Transformer` 或预封装的 attention 算子。

完整批次为 `[B,L]`。`inputs=ids[:,:-1]`、`targets=ids[:,1:]`，所以 logits 为 `[B,L-1,13]`。labels 中 PAD 改成 `-100`，只在有效目标上归约：

$$
\mathcal L=-\frac{\sum_{b,t:\,y_{bt}\ne -100}\log p_\theta(y_{bt}\mid x_{b,\le t})}
{\#\{(b,t):y_{bt}\ne-100\}}.
$$

attention 同时屏蔽未来 key 和 padding key；padding query 的输出仍可计算，但不参与 loss。每条序列以有效 BOS 开头，避免出现整行 attention 分数全为负无穷的情况。验证时先累加所有批次的 NLL 与有效 token 数，再相除；不能直接平均长度不同批次的平均 loss。

优化器是 AdamW，weight decay=0.01，梯度裁剪阈值 1。两种学习率使用相同模型初始化、批次索引随机流、步数与有效 token 总数，只改变学习率。单种子对照能说明这一次运行发生了什么，不能证明普遍最优学习率。

## 实际结果与如何解读

2026-09-26 默认配置实际运行结果如下，精确数值、有效 token 数、环境和耗时以 JSON 为准。

| 学习率 | 初始训练 loss | 最终训练 loss | 初始验证 loss | 最终验证 loss |
| --- | ---: | ---: | ---: | ---: |
| 0.001 | 2.563573 | 0.591463 | 2.570013 | 1.053525 |
| 0.003 | 2.563573 | 0.527196 | 2.570013 | 1.187625 |

较大学习率在这次运行中训练 loss 更低，验证 loss 却更高。它至少说明不能仅凭训练 loss 选模型；验证差异是否主要来自 EOS 长度偏好，是后续可做的错误分解，而非本实验已经证明的原因。每组训练与定期评测约数秒；JSON 的耗时不包括解释器启动、最终数值检查与文件输出。

学习率 0.001 的一条实际 greedy 生成是：输入 `7 8`，续写 `9 0 1 2 3 4 5 6 <EOS>`。下降方向输入 `2 1` 时续写 `0 9 8 7 6 5 4 3 <EOS>`。完整四组提示和停止原因均保存在结果文件中；生成示例只做定性检查，验证指标由全部保留序列计算。

## 已完成的关键检查

| 检查 | 实际验证内容 |
| --- | --- |
| label shift | 用可手算样本确认只移位一次 |
| padding ignore | 解析 CE 对照；被忽略位置 loss 梯度严格为零 |
| 因果不泄漏 | 改写未来 token，固定前缀 logits 最大差为 0 |
| 添加右 padding | 有效 token NLL 仅有浮点容差内差异 |
| 验证归约 | batch size=1 与 17 的 token 平均 loss 一致至容差 |
| 更新数值 | 每一步梯度、损失与更新后参数都为有限数 |
| 学习发生 | 训练 loss 至少下降 30%，验证 loss 低于初始 |
| 保存/重载 | 临时 checkpoint 重载前后 logits 最大差为 0 |

这些检查出现失败时脚本会抛错，而非仍然打印成功。自定义更少训练步数或不同学习率可能无法达到学习下降门槛，这应如实视为该配置未通过当前验收。

## 下一步练习

1. 将验证损失分成首个数字、方向确定前、确定性后续数字和 EOS 四类，检验长度偏好的解释。
2. 在独立目录增加两个随机种子，比较学习率排名是否稳定。
3. 做“固定单条序列可过拟合”实验，区别优化器/实现错误与当前数据的内在不确定性。
4. 完成 CPU 解释后再单独测 GPU 峰值显存与吞吐，披露设备与配置，不把本次 CPU 耗时换算为 GPU 成本。
