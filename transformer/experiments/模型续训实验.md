# 微型语言模型完整检查点续训实验

这个实验把 [tiny_causal_lm.py](tiny_causal_lm.py) 的真实语言模型训练接到完整检查点恢复上。默认让一个分支连续训练 40 步，另一个独立分支训练 20 步后保存到磁盘，重新创建模型、AdamW 和采样器，再加载状态并继续 20 步。恢复后的每一批索引、每一步损失和参数都必须与连续训练严格一致，最后再比较验证结果。

验收还包含两个故意写错的恢复分支：省略 AdamW 状态，或把批次采样器重新设回初始种子。它们必须产生可检测的下一步差异，否则脚本会失败。这样可以区分“权重能够加载”和“训练轨迹能够继续”。这是 [项目 A](../../references/年度学习任务与验收.md#project-a) 的续训机制补充；只涉及合成数字语法和当前 CPU 配置，不据此宣称完整自然文本训练项目已经完成。

## 运行命令与输出保护

在仓库根目录运行统一入口：

```powershell
python scripts/run_lesson.py lm-resume
```

统一入口把本轮检查点、`summary.json` 与 `resume_comparison.csv` 放在 `study_runs/本轮时间戳_lm-resume/artifacts/`，父目录另有 `console.txt`、`run.json` 和 `结果说明.txt`，便于同时查看原始日志、执行状态与中文解释。`artifacts` 是新建的实验产物目录，满足脚本的非空目录保护要求。

也可以直接指定已经安装的解释器：

```powershell
& 'D:\anaconda\envs\pytorch_env\python.exe' -X utf8 transformer/experiments/lm_resume_lab.py
```

直接运行默认使用 `seed=7`、`steps=40`、`split-step=20`，输出到 `study_runs/lm_resume_日期_时间_微秒`。每次运行的目录独立，保留两份实际权重检查点、JSON 汇总和逐步 CSV。代码仅使用 PyTorch 与 Python 标准库，不下载数据或预训练权重，也不安装依赖。

需要改动种子或中断位置时，使用明确参数；`--output-dir` 必须是新目录或空目录：

```powershell
& 'D:\anaconda\envs\pytorch_env\python.exe' -X utf8 transformer/experiments/lm_resume_lab.py --seed 11 --steps 30 --split-step 12 --output-dir study_runs/lm_resume_seed11
```

已有非空目录会被拒绝；文件写入也使用独占创建，防止同名文件被覆盖。`study_runs` 已列入仓库忽略规则，运行产物留在本地。参数要求 `0 <= seed <= 2**63-2`、`steps >= 2`、`1 <= split-step < steps`；例如只把步数设成 10 时，还必须同时把默认中断位置 20 改成 10 以内。

## 模型与数据的训练规则

[lm_resume_lab.py](lm_resume_lab.py) 复用已有 `TinyCausalLM`，不改动模型实现。它有 14,112 个参数、单层 pre-LN、隐藏维度 32、2 个 attention 头、上下文容量 16、GELU 和学习式位置嵌入，没有 dropout。训练计算使用 CPU float64，开启确定性算法，计算线程与 interop 线程各为 1；模型按已有实现随机初始化后转换为 float64。

训练集是数字长度 6、8、10 的 60 条完整序列；验证集是数字长度 7、9 的 40 条完整序列。每个长度枚举 10 个起点与递增、递减两种方向，数字按模 10 循环，并添加 BOS 与 EOS。完整序列在训练和验证之间不重叠，但语法与部分前缀共享，验证长度位于训练长度范围内。验证计算共 360 个有效目标 token，属于长度插值检查。

每步用独立的 CPU `torch.Generator` 通过 `torch.randint` 有放回抽取 16 条序列。`batch_ids` 是合成训练集中的序列索引，不是 token 的词表 ID。输入与标签只移位一次，PAD 标签改为 `-100`；先累加有效 token 的交叉熵，再除以有效目标数。AdamW 的学习率为 0.003、betas 为 0.9 和 0.999、eps 为 1e-8、weight decay 为 0.01；梯度范数裁剪到 1，显式关闭 foreach 与 fused 路径。

验证沿用模型实验的 token 加权归约：所有验证批次的 NLL 总和除以有效目标总数。训练比较始终使用相同数据、初始种子、更新次数和优化配置；完整恢复分支还必须接上相同的批次随机流。

## 检查点保存哪些状态

检查点只包含 tensor、数字、字符串、布尔值以及由这些对象组成的字典、列表和元组。每个分支都从本次运行保存的磁盘文件读取，使用 `torch.load(..., map_location="cpu", weights_only=True)`，随后验证 schema、配置、数据摘要和步数。`weights_only=True` 是受限加载方式，不是对任意来源文件的真实性担保；本实验读取自己刚创建的文件。

| 状态 | 保存字段 | 恢复意义 |
| --- | --- | --- |
| 模型参数与 buffer | `model_state` | 恢复 embedding、attention、MLP、归一化、输出层及因果 mask |
| AdamW 状态 | `optimizer_state` | 恢复每个参数的 step、一阶矩、二阶矩与参数组配置 |
| 已完成的更新数 | `global_step` | 下一次更新应从该步之后开始，避免多训或少训 |
| 已处理有效 token 数 | `processed_tokens` | 接上统计口径，不把恢复后的局部计数误当全部计数 |
| Python 随机流 | `rng_state.python` | 恢复 `random` 的内部状态；原始元组可受限加载 |
| PyTorch CPU 随机流 | `rng_state.torch_cpu` | 恢复框架全局 RNG；重建模型时的随机初始化会先消耗它 |
| 独立采样随机流 | `rng_state.batch_generator` | 接上实际用于训练批次的 RNG；只重设 seed 会从头抽样 |
| 实际训练与模型配置 | `config` | 核对模型维度、优化器超参数、dtype、采样规则和训练计划 |
| 数据身份 | `data_identity` | 对 token 定义及按原顺序排列的完整训练、验证序列计算 SHA256 |
| 格式标识 | `schema_version` 与 `experiment` | 拒绝错误格式或其他实验的检查点 |

恢复顺序是创建新模型和新优化器、受限加载文件、核对元数据、加载权重与 AdamW、最后恢复 RNG 和独立 Generator。新模型刻意使用不同初始化，代码确认新参数与存档参数不同，避免误用原对象造成“恢复成功”的假象。随机状态必须在对象创建之后恢复，否则模型初始化会再次推进已恢复的 PyTorch RNG。

保存点位于一个完整的 `optimizer.step()` 之后。下一步会先执行 `zero_grad(set_to_none=True)`，没有待提交的梯度累积，所以本实验无需存储上一批的 `.grad`。如果把保存点移到一次累积更新的中间，这个条件就不再成立。

本模型的全局 torch RNG 用于随机初始化，训练阶段没有 dropout；Python `random` 也没有决定实际批次。因此脚本保存并核对这两种全局 RNG 的完整状态，还在不消耗真实流的克隆上核对接下来的随机数。这证明当前状态能够恢复，但没有把本模型说成做过 dropout 恢复测试。实际批次随机性由独立 Generator 决定，错误对照直接验证它的作用。

## 四个分支如何比较

连续分支不在中断点保存或重建对象，直接接着更新到总步数。独立的中断分支从同样的初始种子重新训练到中断点，先确认此前每批索引、损失、参数和 RNG 与连续分支一致，再写入检查点。随后，三个恢复分支分别重新读取该文件，避免它们共享并修改同一份 AdamW tensor 状态。

| 分支 | 中断后的处理 | 内置验收 |
| --- | --- | --- |
| `continuous` | 原对象直接继续 | 作为逐步参照，保存所有训练步的损失和参数快照 |
| `resumed` | 完整恢复所有状态 | 全部批次索引、每步 loss、每步参数、最终验证、最终优化器和 RNG 严格相等 |
| `missing_optimizer` | 恢复权重与 RNG，使用新 AdamW | 首批及全部批次仍相同，第一步更新前 loss 相同，第一步更新后的参数必须不同 |
| `missing_batch_generator` | 恢复模型、AdamW 与全局 RNG，采样器回到初始 seed | 续训首批索引必须不同，第一步更新后的参数必须不同 |

AdamW 的历史矩会影响参数更新，却不会改变该步更新之前的前向 loss。只看恢复后的第一条 loss 时，遗漏优化器的分支可以完全相同；必须比较完成紧接着的一次 `optimizer.step()` 后的参数。最后都训练到同样步数，即使验证 loss 很接近，仍不能掩盖训练轨迹已经改变。

所有训练步还检查 loss、梯度、更新后参数是否为有限数，并要求模型参数实际发生变化。完整恢复使用严格的相等比较，错误对照要求下一步参数最大差大于 `1e-12`。不满足要求时抛出异常，成功时退出码为 0。任何自定义配置若碰巧无法区分错误分支，也会如实失败；脚本不会为了通过而把检测门槛改成恒真。

连续与完整恢复分支的初始验证 loss 为 `2.570013258`，最终为 `1.183015417`，最终 token accuracy 为 `0.702777778`。模型参数相对初始值的最大变化为 `0.125660251`，所以零差异来自两条真实更新轨迹相同，而不是模型没有训练。两个错误分支的最终验证值分别为 `1.183374307` 和 `1.190511355`；第一种错误的验证 loss 很接近连续分支，但参数和中途损失已经出现明显差异。

另行检查了非法种子、总步数小于 2、中断步为 0、中断步等于总步数，以及向已有结果目录写入的拒绝行为。已有四个产物的 SHA256 在拒绝前后保持一致。还测试了允许边界 `seed=0, steps=2, split-step=1` 与 `seed=2**63-2, steps=3, split-step=2`；两次都通过实际训练对照。修改 checkpoint 的模型维度、数据摘要或步数后，元数据校验明确拒绝加载。

## 如何阅读结果文件

| 产物 | 内容 |
| --- | --- |
| `checkpoint_step20.pt` | 默认中断点的完整训练状态；自定义中断位置会改变文件名 |
| `checkpoint_final.pt` | 完整恢复分支训练结束时的全部状态，`global_step=steps` |
| `summary.json` | 环境、实际配置、数据摘要、四分支验证、各项误差与通过状态 |
| `resume_comparison.csv` | 连续分支所有步，以及三个恢复分支各自续训步的实际 batch IDs、loss、有效目标数、梯度范数和参照误差 |

CSV 的 `loss` 是该批在参数更新之前的 token 平均损失，`reference_parameter_max_abs_difference` 是完成该步更新后与连续分支的参数差。连续分支自身的两列参照误差当然为 0，恢复分支的误差则由实际 tensor 相减计算；其中两个故意省略状态的分支应出现非零差异。`summary.json` 的 `comparisons.complete_resume` 汇总逐步对照，`checks.status` 为 `passed` 表示所有内置断言已完成。

## 下一步扩展边界

当前恢复使用同一进程中的磁盘保存、独立对象重建和重新读取文件，覆盖本实验真实参与训练的全部状态。它没有测试操作系统进程被终止后的外部重启流程，也没有单独提供读取任意旧检查点继续新训练计划的 `--resume` CLI。要做生产续训入口，需要另行定义允许改变的训练计划字段、检查点来源与兼容策略。

当前模型没有学习率调度器、AMP GradScaler、GPU RNG、多 worker DataLoader、梯度累积或分布式状态，因此检查点没有虚构这些字段。扩展到这些机制后，应分别保存并恢复调度进度、缩放状态、CUDA RNG、采样器或数据游标、累积进度和各 rank 状态，再重做紧接下一步的对照。

更换设备、PyTorch 版本、dtype、线程或数值内核后，不能预先保证逐位相同。GPU 显存和吞吐仍需在对应设备上实际测量；这里不提供从 CPU 耗时推算的 GPU 数字。自然文本、长序列、分布式训练与多种子学习质量比较也不在本次验收范围内。
