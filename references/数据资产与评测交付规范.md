# 数据资产与评测交付规范

本规范用于[项目 B 和项目 C](年度学习任务与验收.md#project-b)及小模型数据质量实验。要交付的不是一个整理过的 JSONL 和一张平均分表，而是能说明每条数据来自哪里、为什么保留、怎样分词和切分，以及模型变化是否在独立题目上成立的记录。算法、数据工程与评测可以选择一条深耕，但三者的输入输出仍要接得起来。

**本文是待由学习者实现并运行的交付规格。字段表、目录和 JSON 是教学约定，不代表本轮已完成真实 tokenizer 数据集、模型训练或独立评测。** 文中的 `null` 表示未生成或未测量；`example_only: true` 的样例不得当作正式资产或成绩。真实运行应保留自己的来源、数量、hash、状态与失败证据。

先做[数据资产实验](../post_train/experiments/数据资产实验.md)，理解标准库能完成的来源/许可记录、过滤、精确去重、显式题族分组、切分与重建检查；其 `data.jsonl`、`audit.jsonl`、`manifest.json` 和 `summary.json` 是教学起点。该实验不等于自动语义近重复识别，没有接入真实 tokenizer，字符计数不能被命名为模型 token 数。本文的近重复与真实监督统计仍需后续实现；训练阶段接入要求见[真实模型训练与验收](../post_train/experiments/真实模型训练与验收.md)。

在仓库根目录执行 `python .\scripts\run_lesson.py data-asset` 可运行这个已实现的教学起点，输出位于本次独立运行目录的 `artifacts/`。教学脚本使用的简化字段由实验文档说明；本规范的 schema 是真实项目的扩展契约，不宣称当前教学脚本已经实现全部字段与门禁。

## 1 先冻结资产用途和实验问题

每个资产写清用途：预训练文本、SFT 示范、DPO 偏好对、RL 训练提示、开发集、最终评测集或任务外回归集。它们可以来自相关来源，但不能仅改文件名就宣称彼此独立。SFT 回答是监督目标，DPO chosen/rejected 是同提示偏好，RL 训练 prompt 配有奖励规则；最终评测还需要独立判分协议。

先登记最小任务定义、允许输出形式、主要指标、样本范围、预算和验收失败条件。例如可解析算术任务要说明允许整数、小数或等价表达，是否要求固定答案字段，是否核验中间推理，超长和多答案怎样处理。答案正确与推理每一步正确是两个不同主张；只检查末答案时就只报告这一范围。

数据质量对照先固定总训练预算，再选择一个变量，例如过滤规则、去重、数据配比或可验证标签质量；保留未处理基线和对应 split。过滤后样本量变小也是实验变化，要同时披露样本/token/更新预算，不能把数量和质量混合变化解释为单独的过滤收益。

DeepSeek 官网当前岗位文案支持按算法落地、数据工程或评测方法论选择深耕方向；本规范是据此与项目需求制定的学习交付标准，不是招聘方发布的固定验收清单。系统岗位的算子、RDMA 和集群工程不被提升为所有算法候选人的硬条件。[官方后训练岗位](https://app.mokahr.com/social-recruitment/high-flyer/140576#/job/5d75f4cd-f626-4f73-80c1-e53b2073de76)、[官方招聘入口](https://talent.deepseek.com/)。2026-10-02 核验的官方页面资源内岗位快照日期是 2026-09-28，实时在招状态未另核验。

## 2 资产目录与逐阶段放行

正式产物放入 `study_runs/data_assets/<asset_id>/<build_id>/`，每次构建独立保存。少量可公开、自编且许可清楚的教学输入可在仓库保存；大体积原始数据与权重不随报告混入版本控制。规范中的目录约定可由实现映射到等价路径，但 manifest 必须能够找到每个产物。

```text
study_runs/data_assets/<asset_id>/<build_id>/
  manifest.json
  build.json
  00_sources/       source_registry.jsonl, raw_input_index.jsonl, retention_plan.json
  01_materialize/   normalized.jsonl, lineage.jsonl
  02_audit/         audit.jsonl, duplicate_groups.jsonl, label_checks.jsonl
  03_split/         split_assignments.jsonl, split_lock.json, leakage_report.json
  04_tokenize/      tokenized.jsonl, alignment_samples.jsonl, mask_statistics.json
  05_release/       data.jsonl, summary.json, reconstruction_check.json
  06_retention/     retention_review.json, tombstones.jsonl
```

| 阶段 | 输入与产物 | 门禁 |
| --- | --- | --- |
| 00 来源 | 原始输入索引、来源版本、许可与保留计划 | 每个来源的允许用途已确认；缺许可的来源隔离 |
| 01 物化 | 标准化记录与逐样本血缘 | 能从输入和确定性配置重建文本/标签/样本 ID |
| 02 审计 | 过滤、重复、空样本、长度与标签审计 | 所有拒绝/隔离有理由；植入的已知错误被检出 |
| 03 切分 | 组分配、冻结清单与泄漏报告 | 题族、重复组及指定来源组不跨 split |
| 04 分词 | 真实 token、按用途适用的 labels/mask 和统计 | 版本固定；SFT/DPO 对应监督不空；RL/eval 纯提示的监督记 `not_applicable` |
| 05 发布 | 最终数据、hash、计数与重建结果 | 产物可回读、引用齐全、同输入重建一致 |
| 06 保留审查 | 保留状态、应到期项与删除/撤销记录 | 审计状态明确；实际删除与计划删除分开报告 |

`build.json` 至少记录构建时间、代码 commit/diff hash、解析与标准化配置、seed、命令、输入版本、输出 hash、退出状态和实际阶段状态。阶段失败就保存失败结果，正式 manifest 不写 `released`。动态获取的数据若不能冻结完整输入，记录这一限制与重新获取条件，不宣称字节完全可重建。

## 3 来源输入与样本 schema

### 原始输入索引

原始输入不能只有一个可能随时变化的 URL。公开源记录 URL、revision/发布日期、抓取时间和实际内容 hash；本地源记录相对引用、文件 hash 与获取说明；合成数据记录生成器代码版本、模板、参数和 RNG。来源为空不意味着“无版权”，公开可访问也不自动意味着允许训练。

| 字段 | 类型或例值 | 说明 |
| --- | --- | --- |
| `source_id` | 稳定字符串 | 来源登记表的主键，不随输出文件名变化 |
| `source_type` | `self_authored` / `public_dataset` / `synthetic` | 根据实际生成过程填写 |
| `url_or_input_ref` | URL 或本地相对引用 | 不含凭据、cookie 或签名密钥 |
| `source_revision` | revision、日期或内容标识 | 区分 URL 相同但内容不同的版本 |
| `retrieved_at` | UTC 时间 | 与源发布日期、构建时间分别保存 |
| `raw_sha256` | 原始字节 hash | 校验内容，不以文件名代替 |
| `license_id` 与 `license_ref` | SPDX 或明确自定义许可及文本引用 | 保存允许使用的依据 |
| `allowed_uses` | 用途数组 | 训练、衍生、公开分发是否允许分别判断 |
| `retention` | 策略、期限/审查日期、存储方式 | 不适用期限时说明长期保留依据 |
| `generation` | 可选对象 | 合成器版本、参数、seed 与父来源 |

不要读取或保存账号凭据，也不要把无必要的个人信息引入教学数据。许可、敏感性或删除权存在疑问时先隔离该来源，继续使用许可清楚的小规模输入；不需要为了完成实验收集更多真实个人资料。

### 单条标准化样本

样本 ID 应由稳定来源主键和源内记录身份确定，或按明确的规范化内容构造；生成方法写入 manifest。**原始字节 hash、规范化内容 hash、token 序列 hash 是不同对象。** 不能一列统称 `hash`，也不能用 Python 进程随机化的 `hash()` 作为跨运行稳定 ID。

| 字段组 | 必须字段 | 用途 |
| --- | --- | --- |
| 身份 | `sample_id`、`source_id`、`source_record_id`、`parent_sample_ids` | 从派生样本回到原始记录 |
| 内容 | 按用途选择 `text`/`document`、`prompt`/`target`、`chosen`/`rejected`，以及 `task_type` | 预训练文本、纯提示、监督与偏好语义分别声明 |
| 标签 | 适用时记录 `label_source`、`label_version`、`label_check_status` | 区分人工、公式、教师生成和未核验标签；纯文本/提示无标签时记 `not_applicable` |
| 分组 | `family_id`、精确重复组、近重复组、可选来源文档组 | 题目变体与泄漏控制 |
| 切分 | `split`、`split_group_id`、`split_version` | 对应冻结切分清单 |
| 审计 | `filter_status`、`filter_reason_codes`、`audit_ref` | 能解释保留、拒绝或隔离 |
| hash | 原始、标准化内容、可选 token hash | 验证不同处理阶段 |
| 分词 | tokenizer/revision、模板 hash、有效/监督 token 数 | 比較成本和监督范围 |
| 保留 | 继承来源保留策略、撤销状态 | 追踪派生资产应否随源撤销 |

  "source_record_id": "example-001",

## 4 过滤重复与标签审计

每条输入写一条或多条审计事件，包含 `sample_id`、`rule_id`、`rule_version`、`stage`、`decision`、检查值、理由和输出引用。计数应能满足“输入总数等于保留、拒绝与隔离的唯一样本数之和”；多规则命中数另外统计，不能把同一条样本重复计入总拒绝量。

| 检查 | 最小实现 | 仍需说明的边界 |
| --- | --- | --- |
| 空内容 | 按资产用途检查必需的 text、prompt、target 或两偏好回答非空 | 不要求纯提示有 target；空角色、纯控制 token 与缺字段也要检测 |
| 长度 | 记录字符数；接入 tokenizer 后记录真实 token | 字符阈值只是预筛，不能冒充模型长度 |
| 精确重复 | 对登记规范化内容算稳定 hash | 规范化规则会合并或保留哪些区别 |
| 近重复 | 可用 MinHash、相似度或人工复核，记录方法版本 | 不是只改大小写后的精确 hash；漏检与误合并需抽查 |
| 题族变体 | 显式 family/template/生成参数分组 | 换数字、改写、同源问题仍可能泄漏 |
| 标签 | 可验证任务独立求解或测试；开放任务抽样复核 | 只查字段存在不能发现错误答案 |
| 偏好方向 | 同 prompt、非相同回答、偏好标签可追溯 | 正确性不等同全面质量，偏好噪声需登记 |
| 泄漏 | 答案是否出现在输入、组是否跨 split | 合法上下文中的信息与意外标签泄漏需区分 |

对合成算术标签，使用能够独立验证目标的公式或求解程序，保存输入操作数与期望解，而不是把原标签读回来当正确答案。对开放任务、推理过程或无法机械判定的标签，登记抽样计划、判据、人工/独立复核结果与争议；无法验证的部分标成 `unverified`。不自动把争议样本都改成模型当前最喜欢的答案。

必须在一个单独的教学错误集植入：一组精确重复，一组已知题族/改写重复，空 prompt 或空回答，一条标签错误，以及一条超长或截断导致监督为空的样本。保存预期命中、实际命中与未检出原因。近重复算法尚未接入时，可通过显式 group ID 检出已知题族，但不能据此宣称检测了未知语义重复。

## 5 先按组冻结切分再做分词

切分单位不是 JSONL 行号。先把精确/近重复组、题族以及任务要求的同来源文档关系合并为禁止跨 split 的关联组件，再对 `split_group_id` 确定性分配。尤其注意传递关系：A 与 B 重复、B 与 C 同族时，不能把 A/C 分开只因为它们没有直接边。

SFT 示例、DPO 对和 RL 提示若来自相同问题，也要继承同一切分身份。按一个全局冻结题目清单分配，随后各阶段从各自 split 获取数据；不能每个文件独立随机切分。切分 seed、稳定分组键、hash 算法、比例和排序方式都写入 `split_lock.json`。小数据按 hash 分桶不保证精确比例，也不保证所有桶非空，需报告实际分配。

train 用于参数更新；dev 用于阈值、超参数和协议调试；eval 用于阶段报告。冻结后改变去重、题族定义或过滤规则会改变评测分布，应产生新资产和新协议版本，而非沿用旧分数。eval 不参与训练 reward 调参或“难度太高所以删题”等开发决策；确需修复错误标签时保存修订理由，重算所有对照模型并标明新版本。

泄漏报告至少列各 split 的样本数、题族数、重复组数、来源分布，以及 exact/near/family/source-group 跨 split 交集和具体 ID。方法不支持的检测列为 `not_implemented`，不能写零；零必须意味着实际检查过且未命中。

## 6 真实 token 与监督 mask 统计

在冻结标准化数据上接入真实 tokenizer，保存版本、模板和特殊 token。逐位置监督检查见[真实 batch 规格](../post_train/experiments/真实模型训练与验收.md)。正式 `tokenized.jsonl` 保存 input IDs、attention mask、labels、移位目标 mask、长度、EOS/截断状态与 source sample ID；hash 应以固定编码的序列化约定产生。

这些字段按用途解释：SFT 要有有效回答监督；DPO 要有两条完整回答的计分 mask；预训练文本采用登记的 next-token 监督范围；RL 训练提示与评测 prompt-only 资产可只有 input/attention，尚未生成回答时将回答 labels/mask 与监督统计记 `not_applicable`，不能判为空监督失败。RL 生成后的动作 mask 在 rollout 资产中验收。评测 gold 如有，应单独存储且不拼进模型提示。

| 统计项 | 全资产与逐 split 必须报告的值 | 解释 |
| --- | --- | --- |
| 长度 | prompt/answer/total token 分布与极值 | 不把字符数填进这一栏 |
| 监督 | 有效监督 token 总数、每样本分布、零监督数量 | 决定 SFT loss 分母与真实更新预算 |
| 角色 | prompt、answer、EOS、PAD、工具文本的监督数量 | 与登记的监督规则核对 |
| 截断 | 截断数量/比例、失去答案或 EOS 的数量 | 说明拒绝/保留政策及其影响 |
| 偏好对 | chosen/rejected 的有效 token 和长度差分布 | 防止长度变化被误认为质量差异 |
| 归约 | token 平均/序列平均与实现接口 | 保证统计与 loss 使用同一监督范围 |
| 质量桶 | 各题族、来源、能力桶的监督与保留数量 | 识别过滤产生的分布偏移 |

按编号屏蔽 PAD 时若 PAD 与 EOS 共用，会误删结束监督；按输入角色直接填移位 mask 会错过第一个答案 token。抽取短、长、EOS 共用与截断四类实例打印 token/label/mask，手工确认有效数；必须与正式统计一致。需要监督或回答计分的 SFT/DPO release 门禁应拒绝相应的零有效样本，不能靠把 loss 分母加 epsilon 掩盖空监督；无回答的 RL/eval 纯提示用途则按前述适用性检查。

下面是**有效 JSON 的统计占位**，没有真实测量值。若先完成标准库预筛，应另外命名 `character_statistics`，保留本段 `tokenizer_status: not_run`，不要用字符统计填入 token 字段。

  "example_only": true,
  "asset_id": "TEACHING_ASSET_PLACEHOLDER",
  "tokenizer_status": "not_run",
  "tokenizer_revision": null,
  "template_sha256": null,
  "supervision_rule": "answer_and_eos_only",
  "splits": {
    "train": {
      "sample_count": null,
      "supervised_token_count": null,
      "zero_supervision_samples": null,
      "prompt_supervised_tokens": null,

## 7 重建 hash 与保留审计

manifest 枚举输入、代码/config、所有阶段产物及 hash，记载每步输入/输出数量和已实施的检查。重建实验应从原始索引指向的固定输入开始，在新 build 目录重跑，比较标准化记录、样本 ID、分组、split 和最终内容 hash。只读取同一输出文件两遍再比较不算重建。构建时间等动态字段可独立保存；若纳入文件则不能要求字节 hash 不变，应预先定义比较的稳定内容视图。

对 tokenizer 再分别验证 token/mask hash；遇到环境或算法非确定性，披露可重复层级及差异，不将“平均长度接近”称为记录可重建。发布 summary 分别列 `passed`、`failed`、`not_implemented`，例如“精确重复与显式题族检查通过，自动语义近重复未实现，真实 tokenizer 待接入”。

保留计划包含来源允许保留方式、原始与派生资产范围、审查时间、撤销/到期处理和 hash 索引。`retention_review.json` 写明计划状态与实际动作；教学规格不执行删除。真正删除时记录 tombstone：资产/样本 ID、相关派生引用、删除原因、时间、状态以及仍保留哪些不含内容的审计元数据。不得一边宣称来源已删除，一边保留可还原内容的样本缓存或 tokenized 文件。

## 8 冻结评测的三个面板

评测资产另用 `study_runs/evaluations/<protocol_id>/<run_id>/`，保存冻结协议、逐题结果与判分复核。先完成起始模型基线，再依据预先登记的开发资料选择任务与预算；不能看到最终模型表现后重新设计只对它有利的面板。

| 面板 | 选取方法 | 主张与边界 |
| --- | --- | --- |
| 主任务 | 与训练目标相关、但题族/重复组不重合的保留题 | 衡量所选任务是否改善 |
| 迁移 | 冻结未见模板、来源、数字范围、组合难度等一个或多个变化 | 分开报告迁移轴，不能把任意难题称为公平迁移 |
| 任务外回归小面板 | 起始模型已能完成、且与预期使用有关的少量其他任务 | 检查已有能力是否退化，而非要求极小模型掌握通用榜单 |

回归面板可考虑模型起初已有的简单指令遵循、信息抽取或短文本任务；先在开发资料上确认基础能力，记录选择依据，再冻结另一批报告题。如果初始模型该任务接近无能力，保留这一观察，但不把该任务作为唯一的能力保持证据。无需强制大型通用 benchmark；题目数、覆盖与资源限制如实报告。

协议固定 sample ID 与题族、能力桶定义、prompt/template、tokenizer、最大长度、采样设置、每题次数、seed、停止条件、自动 scorer、人工 rubric、人工抽样、主要指标和失败归类。能力桶可以按任务类型、长度、难度、格式、来源或迁移轴设置，必须训练前定义；报告各桶分子/分母，不能只给总体平均。

最终 eval 冻结，dev 可以用于 scorer 调试和模型选择。自动判分与人工准则同样有版本；改 scorer 后应重算全部模型，不仅重算新模型。训练 reward 与最终 oracle 可以共享基础任务定义，但不能只复用同一个未经核验的程序和规则就声称独立验证。需要独立求解/测试或人工交叉核验，并记录共享组件带来的共同错误风险。

## 9 闭合任务开放任务与人工复核

闭合任务有可判定答案，例如算术、结构化字段或在约定测试集上的程序输出。主要指标可以是任务正确率，同时分开格式有效率、解析失败、超时和截断；登记可接受的等价答案及数值容差。不要只删除解析失败回答再计算正确率，导致分母缩小。边界样例需人工检查误收/误拒，程序通过测试也仅支持该测试覆盖范围。

开放任务没有单一 gold，例如解释质量或摘要。先定义 rubric：信息正确性、覆盖、相关性、约束遵循和可读性等，并列可观察证据；使用盲评或成对比较，随机展示顺序，隐藏 checkpoint/训练方法身份，保存评判者版本、顺序、理由、平局和无法判断。自动模型评判可作为辅助，但需抽样人工核验位置偏差、长度偏好和裁判错误；偏好胜率不自动等于事实正确率。

人工抽样必须在查看最终模型输出前预登记：各面板、能力桶的随机样本量/比例、seed、必查边界、所有自动与盲评分歧是否复核，以及预算不足的处理。随机代表性样本和定向错误样本分别报告；不能只挑最好的十个输出做“人工评价”。小预算允许缩小数量，但必须说明覆盖不足，不能把未复核写成一致。

## 10 逐题输出与分歧闭环

```text
study_runs/evaluations/<protocol_id>/<run_id>/
  protocol.json
  checkpoint_manifest.json
  predictions.jsonl
  automatic_scores.jsonl
  blind_reviews.jsonl
  disagreements.jsonl
  adjudications.jsonl
  metrics.json
  cost.json
  report.md
```

| 逐题字段 | 需要保存的内容 |
| --- | --- |
| 题目身份 | `sample_id`、`family_id`、panel、split、能力桶、题目版本 |
| 模型身份 | checkpoint/hash、base/adapter 依赖、tokenizer/template |
| 原始输出 | prompt 引用、原始文本、真实 token、结束/截断状态 |
| 推理预算 | 解码配置、seed、样本次数、输入/输出 token、耗时 |
| 自动评分 | scorer 版本、解析结果、指标、分项、失败理由 |
| 盲评 | rubric、评判者、随机顺序、分数/偏好、理由、无法判断 |
| 复核 | 分歧类型、复核证据、最终裁定或保留争议、规则修订版本 |

把自动判对但人工判错、自动判错但人工判对、偏好高但任务错、reward 高但独立 scorer 低、两位评判者不一致分开记。复核回到原始输出和任务定义，不以“训练分数更高”裁决。规则错误应修订并重算所有对照；模型错误则保留，不修改 gold 来迁就输出。尚无足够证据裁决的记录标成争议，报告数量与主指标对争议处理的敏感性。

闭合任务报告正确数量/全部题目、格式有效率、超时/截断、各能力桶和成本；开放任务报告 rubric 分布、成对胜/负/平、无法判断、复核覆盖和分歧。三面板都保留同题配对结果；样本较少时给计数与不确定性，不能只给小数点后多位的提升。多次评测或多种配置挑最好结果应披露选择过程。

## 11 可主动验证的失败案例

| 植入失败 | 预期拒绝或警报 | 应留下的审计产物 |
| --- | --- | --- |
| 同题换数字后跨 train/eval | family 交集非空，不放行切分 | 关联样本 ID、分组依据、修复后的 split 版本 |
| 精确重复只保留了文件行号 ID | 重建或重复检查失败 | 标准化 hash、来源身份与重复保留规则 |
| 缺许可字段直接标为可训练 | 来源阶段失败或隔离 | source ID、缺失字段、允许用途待核验状态 |
| SFT/DPO 空回答或截断后无有效监督/计分 | token/监督阶段失败 | 原长度、截断规则、有效 mask 计数；纯提示用途不适用 |
| 合成 1+2 的 gold 故意写成 4 | 标签检查命中，不发布错标 | 独立期望答案、标签、检查版本与理由 |
| 用字符长度填入 `token_count` | 统计语义检查失败 | tokenizer 状态、真实分词补齐前的缺口 |
| 未实施近重复检查却写零泄漏 | release 阶段拒绝虚假通过 | 检查状态 `not_implemented` 与计划 |
| 只人工抽取训练后最漂亮的样例 | 抽样协议不符，不能据此报盲评结果 | 预登记清单、实际样本差异与覆盖不足 |
| 训练 reward 同时作最终正确性判据 | 独立评测证据不足 | 共享 scorer 依赖、独立交叉核验或未完成状态 |
| 换了模型模板却沿用旧评测分数 | 协议版本不一致 | template hash、重算所有基线的记录 |
| 回归题起始模型本来不会 | 能力保持解释不成立 | 起始筛查、选题依据、合适面板或限制说明 |

交付时检查一条样本是否能从报告追回来源、审计、split、token/mask，再追回某条真实预测与复核记录；再检查一次完整重建。能走完这条链，才说明数据与评测产物可以被别人复查。尚未实现的近重复、分词、训练、人工复核都明确列出，学习进度因此可判断，也不会把教学结构误写成已取得的实验成绩。
