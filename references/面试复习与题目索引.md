# 面试复习与完整题目索引

本页把各专题的完整题目连接起来。更新于 2026-10-02，共 **287 道主问题与 287 道带答案的面试追问**，分布在 71 份讲义、章节、实验说明和论文阅读卡中。题目按技术面试中常见的定义、原理、手算、排错与项目分析方式原创编写；没有把它们标成某家公司的真实面经。

第一次学习先读中文例子，再做基础题。准备面试时先练核心回答，能解释后再展开公式和工程追问。复杂题可以放在第二遍，不要求第一次就完成 PPO、KL 推导或分布式资源估算。

## 一道题应该给你什么

每道题都使用同一套可独立阅读的结构：

1. **题目**：重述模型、数据、初始量、公式或接口约定；改参数时写出原条件，不依赖“其他不变”。
2. **参考答案**：给出计算中间步骤，或按排查顺序给出依据与判据，不只报结论。
3. **面试追问**：检查你是否理解适用条件、常见误区及工程后果。
4. **追问回答**：给出能说清楚的回答，并区分手算、程序核算与真实训练的证据范围。

手算题要说明 log 的底、loss 求和/平均方式、有效 token、终止条件和更新顺序。实验题要说明固定项、唯一主要改动、预算、输出与验收；开放设计题可以有多种方案，参考答案给出一种方案及判断标准。

## 面试时怎样组织回答

先用一两句话定义概念，再解释它解决什么问题，最后用题目里的具体例子说明计算或数据流。追问时再展开假设与失败条件；不要一上来堆算法名字。

例如问“backward 为什么要清梯度”，核心回答是：PyTorch 的 backward 会把叶子参数梯度累加到 `.grad`；普通单批次更新需在下一次计算前清空；有意做梯度累积时要同时处理有效样本权重和更新时机。再用 w=1、b=0、x=2、y=5、半平方损失，连续两次独立前向得到累积梯度 (-12,-6) 说明。

遇到项目题，依次说明任务、数据切分、模型与基线、预算、指标、实际结果、失败分析及验证边界。把自己的实测与计划分清楚：标准库 loss 核算、真实语言模型训练和 GPU 吞吐是不同交付。

## 后续题目的编写规则

- 新概念与新符号先在正文中定义；题干重述解题所需的约定，让读者不用翻前页猜数值。
- 计算题给全输入、初始化、目标、超参数与边界，答案保留关键中间结果；改条件题同步更新断言和验收。
- 概念题明确比较对象与场景，答案先给核心定义，再说明差异与适用条件。
- 排错题提供症状、形状、数据或日志条件，按能排除的具体原因组织答案。
- 实验题给可执行起点与预期判据，随机结果不预设必然赢家；涉及硬件或框架时写版本和验证状态。
- 每题附常见面试追问及回答；答案包含证据能支持的范围，避免把小实验说成完成真实模型项目。

资料依据可从 [教材地图](参考书籍与课程地图.md)、[术语与符号](术语与符号.md) 和 [版本与验证记录](版本与验证记录.md) 追溯。计算结果与运行记录以对应正文和实验输出为准。
