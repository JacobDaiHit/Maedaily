# 阅读方法与证据标准

[总入口](../README.md) · [论文索引](论文索引.md)

## “什么水平”分成四个问题

| 维度 | 应记录什么 | 不应该怎样替代 |
| --- | --- | --- |
| 发表身份 | 官方论文集、期刊、工作坊、技术报告或预印本；对应版本 | 用作者机构、热度或转发量猜录用状态 |
| 贡献类型 | 新问题、理论、估计器、优化器、数据、系统或评测 | 把任何性能提高都叫新算法 |
| 证据质量 | 假设、对照、消融、重复、评测独立性、资源匹配、可复现资产 | 用“顶会”代替检查实验与证明 |
| 对自己的价值 | 先修知识、与当前项目的关系、值得做的最小验证 | 只看是否最新、模型是否更大 |

本库采用“基础必读、进阶选读、前沿观察”等阅读定位，这是针对当前目标的判断，不是统一学术排名。论文自己报告的结果、笔记作者的解释和本地实际运行结果分别表述。

## 一篇论文的三遍读法

第一遍读省流、问题、结论和限制，判断是否对应自己的问题。第二遍回原文看方法、实验设置、表格与附录，用一句话描述每个对照改变了什么。第三遍选择关键推导或最小实验，尝试找出结论失效的条件。

理论论文要写清状态空间、奖励范围、数据获取方式和覆盖条件；检查定理是在表格、线性特征还是一般神经网络下成立。经验论文要写清模型版本、数据拆分、提示模板、随机种子、推理预算和检查点选择规则。缺失信息直接标注，不能用熟悉的默认设置补齐。

## “用在什么地方”分开写

**论文验证场景**是原文真的做过实验的任务。**后续应用证据**需要可核实的独立论文、产品文档或开源实现。**潜在用途**是基于机制的推测，必须说明还缺什么验证。仿真机器人不等于实体部署；benchmark 搜索问答不等于可直接上线的通用搜索服务。

## 本地实验路径

| 阶段 | 最小产出 | 如何避免误判 |
| --- | --- | --- |
| 0. 框架与微型 LM | 梯度核对、因果模型训练、验证与重载 | 合成语法能训练不等于自然语言能力；CPU 与 GPU 结果分开 |
| 1. 手算与标准库脚本 | Bellman 值、DPO loss、组内优势与 mask | 对照解析答案；脚本成功只说明这些机制检查通过 |
| 2. 小模型 SFT | 数据检查、训练 / 验证曲线、固定测试样本 | 检查提示和答案边界，避免题目泄漏 |
| 3. 偏好对照 | 起始模型 / SFT / DPO，同一评测协议 | 同时报正确率、长度和偏好，披露数据与预算差异 |
| 4. 小规模 RLVR | 验证器检查、采样与更新日志、独立正确率 | 训练奖励与最终评判分离；发现作弊先检查奖励 |
| 5. 论文机制复现 | 一个变量的消融及独立重复 | 优先复现机制，不预先承诺大模型分数或正提升 |

在 8 GB 显存设备上，先量一个批次与短训练。参数高效微调减少某些状态，不会消除激活、生成缓存和多轨迹开销。基础数值实验不需要 GPU；已有微型 LM 在 CPU 实跑，预训练模型上的 SFT / DPO / RLVR 仍需按资源另选配置。

## 更新规则

新论文记录检索日期和固定版本；更新 PDF 时保留旧版识别信息并同步省流，不能让笔记引用 v1 的数字而本地 PDF 悄悄变成 v3。先查官方版本页、作者代码和方法 / 实验正文；只有摘要时明确标成摘要级导读。

新增条目应同时具备：正文导读、原始来源、版本、资料清单条目和索引入口。下载成功还要检查 PDF 结构与来源，失败不能留下伪装为 PDF 的 HTML。更新是按需的人工步骤，本库没有后台定时任务。
