换框架时，最值得迁移的是你对目标函数、张量轴、参数状态和求导路径的理解。API 名字相近并不保证默认初始化、loss 归约与执行方式相同；结果不一致也不一定说明某一框架错了。本章以同一个数学问题建立对照，再讨论动态图与静态图。

[三个短程序](../短程序实验.md)把同一组数写成 PyTorch 与 MindSpore 两版：形状都应是 `[3,3]` 与 `[3]`，梯度都应是 $(-6,-3)$，训练应学到约 $(w,b)=(2,1)$。**先比较这些可见数值，再比较语法**。本次只实跑 PyTorch；MindSpore 程序按固定 2.4.0 文档编写，留给有适配环境时核对。

## 3.2 两套框架表达同一张计算图

设预测为 $\hat Y=XW^\top+b$，其中 $X$ 为 `[B,d]`，存储权重 $W$ 为 `[h,d]`，输出 $\hat Y$ 为 `[B,h]`，$B$ 是批大小、$d$ 是输入维度、$h$ 是输出维度。这是 PyTorch `Linear` 与 MindSpore `Dense` 常用的权重布局；从手写的 $XW$ 迁移时要先确认自己使用的 $W$ 是否已经转置。[MindSpore Dense 2.4.0](https://www.mindspore.cn/docs/en/r2.4.0/api_python/nn/mindspore.nn.Dense.html)给出其公式与形状。

| 数学或工程职责 | PyTorch 2.7 常见表达 | MindSpore 2.4.0 常见表达 |
|---|---|---|
| 带状态的模型 | `nn.Module`，定义 `forward` | `nn.Cell`，定义 `construct` |
| 可训练参数 | `nn.Parameter` | `Parameter` |
| 仿射映射 | `nn.Linear` | `nn.Dense` |
| 求导 | `backward` 或 `autograd.grad` | `value_and_grad` 等函数变换 |
| 训练/评估行为 | `train()` / `eval()` | `set_train(True/False)` |
| 执行形态 | eager，可按需编译 | PyNative、Graph 与局部 JIT |

这个表是职责映射，不是逐行替换规则。例如 PyTorch 的 `.backward()` 默认把叶子参数梯度累加到 `.grad`；MindSpore 的 `value_and_grad` 返回一个同时产出值与梯度的新函数。迁移时必须重新明确“梯度保存在哪里，谁接收它，何时更新参数”。模型前向与训练模式接口可查 [Cell 2.4.0 文档](https://www.mindspore.cn/docs/en/r2.4.0/api_python/nn/mindspore.nn.Cell.html)。

## 3.3 一个足够小的跨框架校验

固定函数 $L(w)=\tfrac12(2w-5)^2$，在 $w=1$ 处应有 $L=4.5$、$dL/dw=-6$。先检查这个函数，再迁移完整网络。

```python
# PyTorch 2.7 表达；完整同类梯度校验已在实验脚本实跑。
import torch
w = torch.tensor([1.0], requires_grad=True)
loss = ((2.0 * w - 5.0) ** 2).sum() / 2.0
loss.backward()
print(loss.item(), w.grad)  # 预期 4.5，[-6]
```

```python
# MindSpore 2.4.0 文档对应教学示例；本机未执行。
import mindspore as ms
from mindspore import ops
ms.set_context(mode=ms.PYNATIVE_MODE)
def loss_fn(w):
    return ops.sum((2.0 * w - 5.0) ** 2) / 2.0
loss, gradient = ms.value_and_grad(loss_fn)(ms.Tensor([1.0], ms.float32))
print(loss, gradient)  # 数学预期 4.5，[-6]
```

若函数额外返回预测值作为日志信息，要明确这些辅助输出不参与求导。MindSpore 2.4.0 的 `has_aux=True` 表示只有首个输出参与梯度；对权重求导则使用 `grad_position=None` 并传入权重集合。具体返回结构要对照 [value_and_grad 文档](https://www.mindspore.cn/docs/en/r2.4.0/api_python/mindspore/mindspore.value_and_grad.html)，不要凭输出元组位置猜测。

## 3.4 动态图与静态图改变什么

PyNative 模式便于按 Python 执行顺序调试和查看中间张量；Graph 模式先把支持的程序结构组织成图，再编译执行，可能获得跨算子优化机会。首轮编译成本、支持的 Python 语法、形状变化是否触发重新编译，都会影响体验与耗时。这里的“静态”不等于只能固定 batch，也不等于永远不能表达数据相关控制流；能力取决于版本、图表示和具体用法。

动态与静态也不是两个互斥阵营。MindSpore 2.4.0 文档给出了动态图中局部 `jit` 的方式，PyTorch 则可以对 eager 程序按需编译。转换失败、回退与重编译等机制要按具体版本核查。首次迁移应先让两端的输入、前向输出、梯度一致，再比较编译性能；不要一开始同时改变框架、精度、模型与设备。

## 3.5 从最小例子迁移到项目 A

完整迁移按五层验证：同一输入和参数的输出；同一标量目标的梯度；同一步优化后的参数；同一短训练的曲线；独立验证集的行为。初始化不同会使第一步就不一致，因此先显式复制数值，而不是期待相同 seed 在不同框架中产生相同随机张量。

语言模型还要核对 LayerNorm 的 epsilon、注意力 mask 真假语义、dropout、词表轴和损失归约。同一个 `[B,T,V]` 张量并不足以说明标签与时间步对应正确。检查点通常也不能仅通过改后缀跨框架读取，需要参数名、布局、精度和模型配置的显式映射。

## 3.6 深入：迁移的是计算契约与状态机

### 把“两个程序相同”分成可检查的层

固定参数 $\theta$ 和批次 $D$，记前向为 $F(\theta,D)$、标量目标为 $L(\theta,D)$、优化器状态为 $S$、更新映射为 $(\theta',S')=U(\theta,S,\nabla L)$。跨框架一致性至少有三层：F 一致、L 与梯度一致、U 与状态一致。最后一层还依赖 dtype、epsilon、衰减、裁剪和调度。前向通过并不蕴含后两层通过。

最小迁移表要列出每个参数的源名、目标名、形状、轴意义、dtype 和是否转置。PyTorch Linear 与本章 MindSpore Dense 都按 `[out,in]` 存储时可直接对应；手写模型若按 `[in,out]` 存储才需要转置。对方阵盲目转置尤其危险：形状仍正确，函数却改变了。

例如手写权重 $A=[[1,2],[3,4]]$ 按 `[in,out]` 定义 `x@A`，输入 x=`[1,0]` 应输出 `[1,2]`。迁移到使用 `x@W.T` 的层时，W 应为 `[[1,3],[2,4]]`；若直接复制 A，得到 `[1,3]`。测试至少使用非对称权重和区分坐标的输入，不能用单位矩阵掩盖布局错误。

### 参数相同，状态仍可能不同

Dropout 的训练模式引入随机掩码；带运行统计的归一化层在训练与推理有不同数据路径。比较时先关闭随机行为并固定所有状态，随后单独审查训练行为。tokenizer 的词表顺序、模板、位置编号和 attention mask 的布尔语义也属于计算契约，不能放在“前处理应该差不多”里。

采用 $L(w)=(2w-5)^2/2$，初值 w=1，学习率 0.1、无动量 SGD，两个框架都应先得到 loss=4.5、梯度=-6，再更新到 w=1.6；但若某端使用旧梯度、求和分母不同或 optimizer 未包含 w，第二步就会分叉。用一行状态记录 `step, input, parameter_before, loss, gradient, lr, parameter_after` 逐项定位第一处分歧。

### 编译优化的前提与测量方式

eager 程序按 Python 实际路径执行；编译系统尝试把可捕获的张量运算组织成图，并为图适用的输入与状态建立条件。形状、dtype、设备或控制路径变化可能改变适用条件，导致新编译、回退或执行不同图。Python 副作用是否捕获、数据相关分支怎样处理，必须查具体编译器与版本，不能用一个“静态图”名词统一解释。[PyTorch 2.7 编译概览](https://docs.pytorch.org/docs/2.7/torch.compiler.html)

测量完整工作负载而非只测一次已热身固定形状：分别报告第一次延迟、稳定阶段、不同长度输入、图变化次数与端到端时间。设编译成本为 C、eager 每次耗时 $t_e$、图执行为 $t_g<t_e$，固定同一图重复 n 次，只有 $C+n t_g<n t_e$ 才摊薄编译成本；频繁重编译时 C 需要多次计入。

### 迁移作业的提交格式

先交数学与数值参照，再交两端代码和版本；未执行的一端明确标为未执行。允许先用 CPU float64 排查，再比较目标精度。若一端不支持目标 dtype，声明变更并重新设容差；不能只为通过检查不断扩大容差。容差应结合数值尺度、归约长度与应用需求解释。

### 题 2：前向一致而梯度差两倍，从哪里排查？

**题目：**两端都实现 $\widehat y=2w$，显式设 $w=1,y=5$，前向输出均为 2。PyTorch 使用 $L_P=\tfrac12(\widehat y-y)^2$，MindSpore 使用 $L_M=(\widehat y-y)^2$。分别求损失与 $w$ 的梯度，说明如何对齐，以及其他类似的梯度尺度差异来源。

<details>
<summary>展开参考答案（先独立作答）</summary>

**参考答案：**$L_P=4.5,\ dL_P/dw=-6$；$L_M=9,\ dL_M/dw=-12$。对齐损失中的 $1/2$ 后再比较。批次 sum/mean、有效 token 分母、额外辅助输出被求导，都会造成类似差异，不能只由前向一致推断训练一致。

</details>

**面试追问：**MindSpore 的 value_and_grad 与 PyTorch backward 在职责上有什么区别？

<details>
<summary>展开追问回答</summary>

**追问回答：**`backward()` 执行反向并累加叶子梯度；`value_and_grad` 构造一个同时返回函数值与梯度的新函数，再把梯度交给更新步骤。若函数返回 `(loss, prediction)`，按本章固定版本可用 `has_aux=True` 明确只有首项参与求导。两者都不能代替优化器更新。

</details>

### 题 3：动态图与图模式怎样公平比较性能？

<details>
<summary>展开参考答案（先独立作答）</summary>

### 题 6：编译何时开始摊薄成本？

**题目：**同一图初始编译 C=0.8 秒，eager 每次 0.02 秒，编译后每次 0.01 秒。包含编译但不含其他开销，求编译模式严格更快所需的最小整数运行次数 n。若每 20 次换一种形状并重新付出相同编译成本，计算连续 100 次的总时间。

<details>
<summary>展开参考答案（先独立作答）</summary>

**参考答案：**需 `0.8+0.01n<0.02n`，即 n>80，最小 81。五组形状各运行 20 次，则图模式 `5×0.8+100×0.01=5` 秒，eager 为 2 秒，固定图的稳定速度优势没有转化成这个工作负载的优势。
