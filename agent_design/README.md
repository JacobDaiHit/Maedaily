# Agent 设计：把语言模型接成可检查的任务系统

从一道“先算 $7+5$，再除以 3”的题开始看本卷：模型提出调用，执行器检查参数并真正计算，返回值成为下一步输入，系统最后核对答案。这样反复“决定 → 执行 → 观察”的整体叫 Agent 系统。第 1 章先认识这些角色，第 2 章处理工具、记忆和检索各自会出什么错，第 3 章再定义什么算完成，以及怎样公平比较。沿着同一个例子读，遇到术语先问它在这条流程中负责哪一步。

新手先读 [工具交互第一课](../入门/工具交互第一课.md)，跟着一次计算器调用看状态、重试与停止，再运行 `python scripts/run_lesson.py agent`。

这部分在 [GOAL](../GOAL.md) 中属于服务后训练实验的系统支撑：理解模型怎样读取证据、调用工具、接收反馈并停止，再判断是否值得用监督微调（SFT，用示范训练）或强化学习（RL，用交互奖励训练）改善其策略。它不把使用 Agent 框架、多 Agent 或更长的推理文字当作能力验收。

## 与年度项目怎样衔接

项目 B 可把一次成功工具轨迹转成示范，但必须区分模型生成的动作 token 与工具返回的观察 token，不能把答案泄漏进提示。项目 C 可研究有限工具预算下的成功率；在接入 RL 前先冻结工具接口与验证器，否则环境改动可能被误当算法收益。

本篇验收产出为：一份系统图、一条含错误恢复的可重放轨迹、一份对照评测计划。目录中的数值状态机只验证控制逻辑，不包含真实模型，不计作真实 Agent 能力评测或模型训练完成项。
