# ReAct：让任务推理与环境动作交替发生

> **30 秒省流：**把一次任务组织成“观察 → 判断下一步 → 工具动作 → 新观察”。这是理解 Agent 控制循环的重要方法论文；它不证明每次加入长推理、工具或多 Agent 都能提高效果。

## 身份、版本与水平

- **原文：**[arXiv 2210.03629v3](https://arxiv.org/abs/2210.03629v3)；[HTML](https://arxiv.org/html/2210.03629v3)；[本地 PDF](../pdf/2210.03629.pdf)。首稿 2022-10-06，所读版本 2023-03-10；资料核验 2026-09-26。
- **已核实发表状态：**ICLR 2023。arXiv 将 v3 标为 ICLR camera-ready；[作者代码仓库](https://github.com/ysymyth/ReAct) 同样标明会议。不是 2022 年 ICLR 论文。
- **阅读判断：**Agent 入门必读的方法锚点，重点是闭环交互与受控消融；“经典、值得精读”是本书判断，会议身份不是实际产品可靠性认证。

## 做了什么

在提示中给出任务推理、动作、观察交替的轨迹示范，主要实验用冻结的 PaLM-540B。Wikipedia 工具为 `search/lookup/finish`；Act 消融删除推理文字，CoT 删除外部动作与观察。论文另有微调实验，不应把整篇概括成“只有 prompting”。[方法第 2–3 节](https://arxiv.org/html/2210.03629v3)

## 实验究竟支持什么

| 原表及协议 | 结果 | 应怎样读 |
| --- | --- | --- |
| 表 1，PaLM-540B，HotpotQA EM | ReAct 27.4，Act 25.7，CoT 29.4 | 优于 Act，但低于 CoT |
| 表 3，134 个 ALFWorld 未见游戏 | ReAct 平均 57%；6 套 prompt 最佳 71%；Act 最佳 45% | 71% 是最佳 prompt 结果，不能当平均 |
| 表 4，500 条 WebShop 测试指令 | 成功率 ReAct 40.0%，Act 30.1%，IL+RL 28.7% | 是基准环境任务完成，非真实购物部署 |

数值来自 [第 3–4 节及表 1/3/4](https://arxiv.org/html/2210.03629v3)。这些对比包含不同训练和提示预算；不能把它们解释为相同总成本下普遍优于 RL。

## 已验证应用与潜在迁移

论文验证了知识问答、事实核验、文本家庭环境与 WebShop 交互。迁移到自己的本地文档助手是可研究方向：接口和目标都需重建、重新评测，不能引用原分数作为自己系统效果。

## 局限与我的阅读判断

工具提供的证据可能空缺，模型可能反复执行同一动作，格式正确也可能判断错误。更可检查的轨迹利于排错，但可读文字不是内部推理忠实性的证明。对当前学习目标，应先复现动作校验、观察记录和停止控制，再考虑复杂规划；这是本书实践建议，不是论文结果。

## 读哪些节，做什么练习

### 阅读题：怎样检验动态动作选择的价值？

**题目：**固定一个 100 题的证据问答集，同模型、检索工具和语料；每题工具调用上限 4、输出上限 1000 token。A 总按固定“检索两次再答”路线；B 每次观察后可检索、换查询或停止。独立验证器检查答案与引用。请设计控制变量、指标和首错分类，并说明为什么一条成功例子不够。
