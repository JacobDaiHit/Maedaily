# Reflexion：把失败反馈写成下一轮可用的记忆

> **30 秒省流：**行动后接收反馈，把失败总结存进上下文，再尝试一次。论文标题中的 verbal reinforcement learning 不表示通过 PPO 或其他梯度方法更新模型权重。收益依赖反馈可靠性与额外试错预算。

## 身份、版本与水平

- **原文：**[arXiv 2303.11366v4](https://arxiv.org/abs/2303.11366v4)；[HTML](https://arxiv.org/html/2303.11366v4)；[本地 PDF](../pdf/2303.11366.pdf)。首稿 2023-03-20，所读版本 2023-10-10；资料核验 2026-09-26。
- **已核实发表状态：**[NeurIPS 2023 主会官方条目](https://proceedings.neurips.cc/paper_files/paper/2023/hash/1b44b878bb782e6954cd888628510e90-Abstract-Conference.html)。本卡实验数值取 arXiv v4，不把不同版本表格混写。
- **阅读判断：**适合理解反馈、重试、记忆与参数训练的区别，方法设计价值高；它不是自我反思总会改善结果的定理。

## 做了什么

系统包含 Actor、Evaluator、Self-Reflection 三种角色。行动轨迹经评分后生成文字反馈，存入有容量限制的记忆供下一轮使用；模型权重不更新。评价可以来自环境或模型，并不保证自动正确。[方法第 3 节](https://arxiv.org/html/2303.11366v4)

## 精确实验与反例

| 设置 | 对照与结果 | 关键条件 |
| --- | --- | --- |
| ALFWorld，134 个任务 | ReAct+Reflexion 在 12 轮尝试中解决 130 个 | 累积解决率，不是一次运行成功率 |
| 表 1，HumanEval Python | GPT-4 80.1%，Reflexion 91.0% | 后者有生成测试、执行与修订流程 |
| 表 1，MBPP Python | GPT-4 80.1%，Reflexion 77.1% | 存在性能下降，不能只引用 91% |
| 表 3，HumanEval Rust 最难 50 题 | 完整方法 0.68；无自反思 0.60；无测试生成 0.52 | 反馈和修订机制要共同检查 |

来源为 [§4.1、§4.3 与表 1/3](https://arxiv.org/html/2303.11366v4)。代码评测输出一个最终候选，内部使用自生成测试；论文将其报告为 pass@1，但不能解释为仅一次模型生成，也不能与无反馈基线视为相同推理成本。

## 应用范围

论文实际测试文本环境决策、HotpotQA 和代码生成。失败摘要可用于本地工具流程的重试，这是可尝试的工程迁移；真实浏览器、支付或多用户生产系统的可靠性并未由这些结果确立。

## 局限与本书判断

错误的自生成测试可能把正确解改坏；错误总结也可能在下一轮继续传播。应把“反馈判对了吗”“下一轮是否利用了反馈”“花了多少额外预算”分开测。自己的验证器未稳定前，先增加可靠日志往往比增加反思次数更有诊断价值。后一句是实践建议，不是原文实验结论。

## 阅读顺序与练习

先读 §3 的接口分工，再读 §4.3 的测试生成、MBPP 负结果与消融表，最后读 §4.1 的跨轮次成功曲线。以下是原创对照设计题，运行结果需另行记录。

### 阅读题：如何区分记忆、重试和反馈的作用？

**题目：**同一 100 题代码集，每题最多 3 次候选、总生成上限 3000 token，每次测试使用相同可见测试反馈，最终以保留的独立测试集评测。三方案分别不带历史、带原始历史、带失败摘要；最终选择规则为可见测试全过则停止，否则用第三份候选。请写控制变量和必须报告的错误，说明最终全过与 pass@1 的区别。

**参考答案：**固定模型、题目、可见测试、独立测试和总预算，历史/摘要占用也计入；报告各轮和最终独立测试通过率、token、测试次数、反馈误判以及修订后退步。最终提交包含此前尝试与反馈，不能称为无反馈 pass@1。摘要的效果须与等尝试、等反馈基线比较。

**面试追问：**自动测试全过就等于程序完全正确吗？

**追问回答：**只说明通过该测试集。测试可能遗漏边界或本身生成错误，需要独立测试与错误分析。
