# 第 3 章：Agent 评测与可靠性

> 目标：把好看的演示变成可复核的实验，区分模型决策、工具执行和任务结果。

前两章已经定义动作、观察、请求校验和失败恢复。现在把“系统会算 $(7+5)/3$”变成可测结论：题目是否算对，是否确实调用过工具，遇到暂时故障时是否在预算内恢复？**评测协议**是运行前约定的题目、预算、成功判据和记录方式；同一协议下的结果才方便比较。

## 3.1 成功需要外部定义

模型输出“已完成”只是一个事件。对算术任务，成功可定义为最终数值正确且证据链可追溯；对检索问答，还要检查引用确实支持主张；对文件操作，则需核对目标文件的实际状态。先写成功判据，再运行系统，否则容易在看到输出后降低验收要求。

将一次任务的观测记为 $\tau=(s_0,a_0,o_1,\ldots,a_{T-1},o_T)$，定义外部评估 $g(\tau)\in\{0,1\}$，测试集上成功率为 $N^{-1}\sum_i g(\tau_i)$。若评估本身由语言模型完成，应抽样人工复核，并记录评判模型、提示、候选顺序及一致性。评判器输出不天然是真值。

## 3.2 同时报告质量、成本和失败原因

| 维度 | 可记录指标 | 容易误读之处 |
| --- | --- | --- |
| 结果质量 | 成功率、事实/格式正确率 | “调用成功”不等于任务成功 |
| 工具使用 | 有效请求比例、冗余调用、恢复率 | 调用越多不代表做得越充分 |
| 成本 | 模型 token、工具次数、耗时 | 只比较次数会遗漏单次调用差异 |
| 停止行为 | 提前宣布完成、预算耗尽、重复循环 | 只统计成功样本会隐藏困难任务 |

对有限预算 $B$，可比较 $S(B)=P(\text{预算内完成})$，而不仅给一个最高分。更复杂系统若只在十倍调用下提高一点成功率，仍可能对某些任务有价值，但应明确成本。重复同一道题多次取最佳结果，还需要说明如何选择最佳；知道测试答案才能选择的上界，不等同于部署系统实际成功率。

## 3.3 建立能定位问题的轨迹

最小日志保存任务 ID、模型与工具版本、每次请求和观察、重试次数、预算变化及停止原因。原始证据与摘要分开保存，错误用结构化类型，不用一段无法统计的“出现问题”。运行含随机采样时记录生成参数与种子；外部服务不可重放时保存当时可公开的返回快照并说明限制。

失败可按最早可确认原因分类：目标理解错误、计划依赖错误、参数不合法、工具故障、证据误读、记忆污染、错误验证、停止条件错误。一个任务可能有多个问题，但先定位最早错误通常更利于修复。仅用最终回答让模型猜失败原因，容易生成看似合理却无日志支持的故事。

## 3.4 从单例到对照实验

先建立小而多样的用例：直接成功、空检索、工具暂时失败、参数错误、相互矛盾证据、重复响应、预算不足。它们检查控制逻辑。随后加入未参与开发的真实任务，评估模型是否能正确选择动作。二者分开报告，不能拿规则脚本通过测试来宣称 LLM Agent 达到某准确率。

在同一题集上比较基线时，固定模型、工具集合、提示信息与预算；每次仅改变一个机制，例如有无失败摘要。对每题保留两个系统的结果，做配对差异；随机生成需要独立重复。若更换模型又增加工具，无法把收益归因于规划策略。统计原则可参照 [推理评测与实验设计](../../post_train/chapters/07_推理评测_蒸馏与实验设计.md)。

## 3.5 两篇经典论文教什么判断

ReAct 的实验不支持“加入推理与工具必然提升所有任务”；Reflexion 的某些代码任务也出现下降。具体数值、模型和反馈预算见 [ReAct 阅读卡](../papers/notes/2022_ReAct.md) 与 [Reflexion 阅读卡](../papers/notes/2023_Reflexion.md)。学习价值在于观察它们如何构造对照，以及哪些机制依赖评估反馈质量。

真实系统中的重试还会改变信息条件。如果第一轮可看到测试反馈，第二轮就不再是无反馈的一次作答。报告单次提交结果时，必须同时披露此前的生成、测试与修订预算，避免把试错收益写成模型自身的一次生成能力。

## 3.6 与后训练项目连接

若准备把成功轨迹用于 SFT，应保留失败轨迹供分析，按任务而非单条步骤划分训练测试，避免相同题目的动作历史泄漏。若准备用 RL 优化工具调用，应先稳定环境、奖励和日志，区分工具观察与策略动作，统计奖励漏洞。[RLVR 的验证器边界](../../post_train/chapters/06_GRPO与RLVR.md) 同样适用。

一个合格的小项目交付应包含：接口说明、固定任务集、可运行控制器、结果表及失败轨迹。模型选择、训练与系统编排可以依次改进；一次把所有环节复杂化，会让负结果难以解释。

## 3.7 练习与提示

1. 某系统调用成功率 99%、任务成功率 40%，接下来查什么？提示：确认参数语义、证据使用和结束验证。
2. 有记忆系统用了三轮，无记忆系统只用一轮，怎样补公平对照？提示：给无记忆系统同样预算并披露选择规则。
3. 为状态机实验增加一个你能预测结果的失败用例。提示：先写预期停止原因，再改输入，不根据输出改判据。
