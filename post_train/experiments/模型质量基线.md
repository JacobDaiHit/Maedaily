# 模型质量基线：先用开发集选模型，再打开冻结评测

这一课接在[模型后训练实验](模型后训练实验.md)之后。上一课证明了真实文本、梯度、采样与参数更新可以复查；这里检查模型是否已经具备可用于后训练对照的算术与 copy 能力。训练仍使用本地字符级因果 Transformer、已有 PyTorch 和 CPU，不下载预训练模型。

前置是能解释回答/EOS mask、独立交叉熵与 greedy 生成。必读是本文的数据协议、开发选择与未通过结果；选读是[纯数据协议](model_quality_data.py)和[公共运行程序](model_quality_lab.py)。本课完成标准是能复查数据族隔离、只用开发集选择的检查点、未通过原因，以及最终面板是否真正保持封闭。达到质量门槛还需实际最终评测证据。

## 为什么要重新建立基线

旧实验的算术分区使用 `key = min(a,b)*6 + max(a,b)`，再按 `key % 7` 分配。当操作数都在 `0..5` 时，`6 ≡ -1 (mod 7)`，所以这个余数等于操作数差值。主面板拿走全部对角题，开发集拿走全部相邻操作数题，训练只剩差值至少为 2 的题族。训练算术答案因此缺少 `0`、`1`、`9`、`10` 和 `-1`。这是由划分规则造成的结构偏移，不能只靠增加训练步数解决。

旧 copy 面板也需要重新解释：训练见过 `copy 3`，面板却要求从 `copy 03` 得到 `3`。它检验未见写法的泛化；起始模型原本没有通过时，就不能把后续表现称为能力保持或遗忘。旧面板和历史结果保留为 `legacy-v1` 诊断，新质量实验使用独立冻结的 `quality-v2` 协议。

## 先固定数据和门槛

[数据协议](model_quality_data.py)不接受随机种子或训练配置来改变切分。算术按规范化操作数对分族，同一对操作数的交换顺序、加法与减法总在同一分区。copy 按数值分族，原样、一个前导零和两个前导零的三种输入写法也总在同一分区。

| 分区 | 样本数 | 内容与职责 |
| --- | ---: | --- |
| train | 340 | `0..9` 算术与 `0..99` copy 归一化的训练来源 |
| dev | 36 | 独立算术族；选择架构与训练检查点 |
| dev_copy | 45 | 独立 copy 数值族；选择时检查另一项能力 |
| eval_main | 34 | 冻结的域内算术主面板 |
| eval_transfer | 120 | 包含操作数 `10/11/12` 的范围外迁移面板，另有未见答案 |
| eval_regression | 45 | 冻结的 copy 归一化面板；合格共同起点建立后用于保持能力的比较 |

算术将包含操作数 0 或 9 的 19 个边界族固定放入训练，保证训练答案完整覆盖 `-9..18`；其余 36 个族用固定 SHA-256 排序，前 10 个进开发集、接着 10 个进主面板、其余进训练。copy 的 100 个数值族另用固定 SHA 排序，70 个训练、15 个开发、15 个最终回归。这是明确包含训练覆盖锚族的协议，并非全部题族随机切分。

程序独立从题目计算答案和数值族，拒绝伪造 family、跨分区语义别名、缺失训练标签和过小面板。冻结数据 SHA-256 为 `db75ec1c32e89dbd887996433778c62a9626ee95a70a5ab229a45736a70f083d`；运行会保存数据、分配规则和实际 hash。

资格门槛在训练前固定：算术正确率至少 **80%**，copy 至少 **90%**，两者格式有效率均为 **100%**，每面板至少 **20 题**。格式只认严格整数答案与正常 EOS 停止，格式有效不等于答案正确。最终主面板至少需 `28/34` 正确，copy 至少 `41/45` 正确，并分别达到 `34/34`、`45/45` 格式有效。

这一定义只覆盖域内算术与 copy 归一化基线。迁移面板单独报告，不作为本课合格条件；域内合格不能推出范围外泛化或通用语言能力。

## 运行与开发选择

在仓库根目录，使用已有的 PyTorch Python 执行：

```powershell
python post_train/experiments/model_quality_lab.py --seeds 17 23 41
```

这里的 `python` 必须指向已安装 PyTorch 的解释器。本轮 Windows 环境已使用 `D:/anaconda/envs/pytorch_env/python.exe` 实跑；在当前 PowerShell 中可明确选择它：

```powershell
& "D:\anaconda\envs\pytorch_env\python.exe" .\post_train\experiments\model_quality_lab.py --seeds 17 23 41
```

其他电脑应换成自己的已有 PyTorch Python 路径。

这个命令显式登记 3 个种子。脚本当前默认 `--seeds 17`；无论登记几个，架构选择只允许固定的 seed 17。默认注册的候选是宽度 32/2 层、宽度 64/2 层、宽度 64/3 层，均为 2 个 attention heads。每个候选训练到 4,000 步，在 `200/500/1000/2000/4000` 步保存检查点并仅运行两个开发面板。

每步从算术和 copy 各采样 16 条，共 32 条，使用回答 token 与 EOS 的交叉熵、AdamW、学习率 0.003 和梯度裁剪 1.0。评测使用 greedy、最多 4 个新 token 和相同停止规则。候选的真实梯度范数、参数变化、训练样本 ID、有效 token 和检查点均保存；这不是把训练 loss 下降当成模型正确生成。

选择函数只接收 `dev`、`dev_copy`。先比较“两面板格式全部有效且 copy 至少 90%”，再比较算术正确率、copy 正确率、较低的开发回答 NLL和较早步数；完全并列保持较早注册的候选。函数会拒绝混入任何最终面板。

选定结果先写入 `selection.json`，固定检查点路径、文件 hash、权重 hash、结构、步数和开发指标。开发资格未通过时，最终数据不会传入评测函数。选择文件或权重后来被修改，也不能打开最终评测。

## 最终评测、多种子与后训练对照

开发通过后，seed 17 使用选中的冻结检查点；其余登记种子使用完全相同的结构和步数重新训练，只做该单个检查点的开发资格检查，不再次搜索预算。每个通过开发资格的种子才会打开最终三面板一次。没有通过的种子会明确记录并保留最终结果为空，不能挑选通过的种子来汇总。

全部登记种子的最终域内门槛都通过，才能称本次多种子基线合格。最终失败不会触发重新选择架构、检查点、训练预算或种子。若要依据最终失败做新研究，应把旧结果作为已使用的信息记录，并另外冻结新的最终评测协议。

后续 SFT/DPO/RLVR 对照应从这份**已经合格的共同 SFT 起点**分支，保存不更新基线和 copy 起始正确题。各分支使用相同冻结题目、模板、生成预算与停止规则，报告配对改善/退化、全部种子和真实训练成本。继续 SFT、DPO、RLVR 的样本、有效更新 token 与采样成本不同，不能只看相同步数就宣称方法更优。

## 当前实际结果与退出码

2026-10-02 的公共完整运行保存在 `study_runs/model_quality_registered_20261002/`，实际摘要为该目录的 `summary.json`。运行耗时 **394.472 秒**，3 个候选各完成 4,000 次真实参数更新，共 **12,000 次**，检查上述 5 个节点，全部未达到开发门槛。按冻结选择函数最终选中的是 **宽度 32、2 层、4,000 步**的检查点；该候选实际使用 **340,233 个有效更新 token**。

| 面板 | 正确 | 格式有效 |
| --- | ---: | ---: |
| dev 算术 | 8/36 | 36/36 |
| dev_copy | 45/45 | 45/45 |

选定检查点落盘后，额外做了一次不参与选择的训练集只读诊断：算术 **130/130**、copy **210/210** 正确。训练题已经拟合，但隔离的算术开发题只有 `8/36`，说明记住训练数据与学到可泛化的算术规则不能等同。copy 归一化在开发集上已成立，也不能补偿算术未达到门槛。

本轮计划种子为 **17/23/41**，实际仅执行 **17** 的开发选择。状态是 `development_unqualified`、退出码 **4**，追加种子明确跳过，`final_metrics=null`；`events.json` 中没有 `final_opened` 事件。最终主任务、迁移、回归面板继续封闭，没有隔离最终成绩可报告。

这里的 `8/36` 和 `45/45` 都是开发成绩，训练诊断也仅来自训练集。它们不能当作隔离主任务、迁移或回归面板的性能；未运行的最终结果不能填 0，也不能由开发指标推算。本段以公共完整复跑为准，早期临时容量诊断不替代这份冻结选择记录。其他运行仍应查看自己目录中的 `summary.json` 和逐题文件。

| 状态 | 退出码 | 应怎样解释 |
| --- | ---: | --- |
| `qualified` | 0 | 全部登记种子的开发与最终域内资格通过 |
| `development_unqualified` | 4 | 开发资格未通过；追加种子跳过、最终保持封闭，`final_metrics=null` |
| `quality_unqualified` | 4 | 开发通过后，存在登记种子未达到开发或最终资格；完整报告失败 |
| 异常导致未完成 | 1 | 数据、计算图、不可变文件或执行路径出错，需要排查 |

退出码 4 是如实交付的质量失败结果。验证程序能阻止偷用最终面板、准确记录该状态的工程测试可以通过；这不意味着模型达到质量门槛。当前不能进行“合格起点上的后训练方法优劣”结论。

## 从哪些文件复查

默认每次使用新的 `study_runs/` 目录，显式输出位置也受不可覆盖保护。优先读取以下文件：

| 文件 | 复查内容 |
| --- | --- |
| `preregistration.json` | 候选、节点、种子、训练配置、源码与协议 hash，先于训练落盘 |
| `protocol.json` | 全部冻结 split、语义族、覆盖报告、选模职责和资格阈值 |
| `development/<候选>/step_*_dev.json` | 各节点开发逐题生成、NLL、资格与选择排序 |
| `development/<候选>/training.json` | 每次真实更新、样本 ID、任务配比、有效 token 和参数变化 |
| `selection.json` | 已冻结的结构、步数、开发指标与检查点身份 |
| `events.json` | 预注册、选定冻结、最终打开或保持封闭的顺序 |
| `seed_*_final.json` | 仅在满足开放条件后生成的最终逐题结果和门槛 |
| `summary.json`、`结果说明.md` | 所有登记种子、跳过理由、最终空值或结果、质量状态与退出码 |

用纯标准库检查数据与门槛，或在已有 PyTorch 环境中一并执行质量工作流测试：

```powershell
python -m unittest discover -s tests -p "test_model_quality*.py" -v
```

数据测试会主动制造 family 篡改、跨分区别名、缺失标签、低于门槛、假 accuracy 和混入最终指标，要求它们明确失败。开发算术未合格时，下一项实验应使用训练/开发资料诊断表示与失败题，并在运行前另行登记候选；当前冻结最终面板继续保留，不能用于选择修改方案。
