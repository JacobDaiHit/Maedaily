# 模型后训练实验：从数学核算进入真实更新

这一课提供可以在 CPU 上运行的字符级因果文本模型，接通 tokenizer、SFT、DPO、在线采样、可验证奖励、策略更新、检查点和逐题评测。它是仓库内从随机权重开始训练的小模型，输入是真实文本，输出通过自回归生成得到。默认不需要下载模型、联网、GPU 或安装 Hugging Face 组件；需要已有的 PyTorch 环境。

先完成[标准库后训练实验](README.md)和[短程序实验](../短程序实验.md)，再运行本课。更完整的项目交付仍按[真实模型训练与验收](真实模型训练与验收.md)逐项完成；本课的一个短运行并不等于独立重复、消融、盲评和年度项目已经全部验收。

实际更新能复查后，继续[模型质量基线](模型质量基线.md)：重新冻结有训练标签覆盖的数据协议，只用开发集选择检查点，基线合格后再做后训练对照。

## 本次完成标准

运行后应能拿着实际文件回答以下问题：

1. 哪些位置属于提示、回答、EOS 和 padding？第一个回答 token 由哪个位置的 logits 预测？
2. 手写 SFT loss 与独立 `cross_entropy` 路径是否一致？真正的模型参数是否有有限、非零梯度并发生变化？
3. DPO 的四个回答 log-prob 来自哪组权重？为什么初始 loss 是 `ln(2)`，reference 在训练后仍相同？
4. 保存的 rollout 是怎样采样的？改变温度后，为什么原始 softmax 概率不能直接当作行为概率？
5. 同快照、同分布、更新前的 ratio 是否接近 1？同分组是否得到零优势，实际奖励信号是否引起 policy 更新？
6. SFT、DPO、RLVR 的独立生成结果是什么？检查点重载是否恢复相同 logits？哪些结果仍然不足以支持方法更优的结论？

## 运行方式

在仓库根目录，使用已有的 PyTorch Python 执行统一入口：

```powershell
python .\scripts\run_lesson.py sft-model
python .\scripts\run_lesson.py dpo-model
python .\scripts\run_lesson.py rlvr-model
```

三个入口分别完成“起始训练 + SFT”“起始训练 + SFT + DPO”和“起始训练 + SFT + 在线采样与 RLVR”。`rlvr-model` 还从同一个 SFT 检查点建立不更新与继续 SFT 的比较支路。默认每次写入新的 `study_runs/` 目录，统一入口的模型文件位于该次运行的 `artifacts/`。

要在一轮中观察所有分支，可以直接运行[模型训练程序](model_training_lab.py)：

```powershell
python .\post_train\experiments\model_training_lab.py --mode all
```

直接运行的默认目录也会自动创建；显式指定目录时，只接受新目录或空目录。程序使用独占运行标记和以 `x` 模式创建的检查点，已有结果和失败记录不会被本课再次覆盖。

统一入口可用 `--` 传递实验参数。例如保持其他配置不变，只改变 DPO 的 beta：

```powershell
python .\scripts\run_lesson.py dpo-model -- --beta 0.1
```

以下命令从本课已生成的本地检查点加载模型与 tokenizer，然后另起一次训练。将示例路径换成自己刚完成的实际输出路径：

```powershell
python .\scripts\run_lesson.py sft-model -- --model-path .\study_runs\你的运行目录\artifacts\final_checkpoint.pt
```

`--model-path` 接受本课格式的实际 `.pt` 文件。检查点内含权重、模型配置、tokenizer 和权重 hash，加载时用 PyTorch 的 `weights_only=True` 并核对格式与 hash；不能用任意其他模型家族的权重替代。这个入口支持“加载已有权重后开启新实验”。保存的 optimizer/RNG 信息便于后续研究恢复逻辑，本课尚未提供无差异的中断续训 CLI。

## 模型、数据与三块评测面板

模型是 1 个 pre-LN Transformer 层，宽度 32、2 个 attention heads、上下文上限 32，float32、无 dropout。注意力同时应用因果 mask 和 padding key mask。tokenizer 以字符为单位，`PAD=0`、`BOS=1`、`EOS=2`，右侧 padding；词表、模板和特殊 token 随每轮结果保存。

固定提示模板是 `Q:{question}\nA:`。例如题目 `2+3=` 的回答文本为 `5`；真实序列由 tokenizer 得到 `[BOS] + 提示字符 + 回答字符 + [EOS]`。SFT 只监督回答与 EOS；起始模型训练阶段则学习所有实际下一 token，二者的有效 token 预算分开记录。

数据和最终评测在训练前固定并保存到 `data_manifest.json`：

| 分区 | 内容 | 独立性与用途 |
| --- | --- | --- |
| train | 小整数加减法、标准写法的 copy 任务 | 唯一训练来源；DPO 和 RLVR 使用其中算术题 |
| dev | 一组独立的小整数操作数族 | 预留开发分区；默认配置不会根据它或 eval 自动选参 |
| eval_main | 独立的小整数操作数族 | 主任务逐题生成 |
| eval_transfer | 左操作数为 7、8、9 的未见操作数族 | 跨操作数范围迁移 |
| eval_regression | 输入如 `copy 03`，目标为 `3` | copy 任务的未见输入写法；单独披露起始能力是否成立 |

算术题用规范化的 `min(a,b):max(a,b)` 操作数对分族。同一对操作数的交换顺序、加法与减法都进入同一分区，因此 `2+3` 和 `3+2` 不会被分到训练和评测两边。程序和测试会拒绝跨分区的同族数据。

所有分支使用同一份冻结评测、greedy 解码、最多 4 个新 token、相同停止规则与样本集合。保存逐题输出、正确/格式有效状态、生成 token 数、耗时和配对变化。主评测只认严格答案与 EOS，不把格式奖励算作正确答案。如果回归面板的起始正确数为 0，`regression_panel_baseline_qualified` 为 false，这轮不能据此证明能力保持。

## 真实图中的 SFT 和 DPO

`token_masks.json` 给出每个位置的真实 token、角色、未移位 label、attention mask 和 loss mask。第一个回答 token 的监督使用最后一个提示位置的 logits；代码只移位一次。EOS 属于回答目标，padding 与提示 label 是 `-100`。改变 mask 或外部再次移位都会被校验拒绝。

SFT 按全批有效回答 token 平均。`checks.json` 核对手写 gather/mask 与独立交叉熵的标量、直接 logits 解析梯度，以及实际模型参数的两条 backward 梯度。提示位置的直接 logits loss 梯度为 0；提示 embedding 仍可能通过 attention 收到梯度。

DPO 从完成 SFT 的权重分支开始，reference 是独立冻结副本。chosen 是训练题的正确答案，rejected 是答案加一；两个回答都使用回答加 EOS 的 log-prob 求和。正式目标是 `softplus(-beta * ((policy_chosen-policy_rejected) - (reference_chosen-reference_rejected)))`，再对偏好对平均。

初始化检查保存四个 log-prob、`u≈0`、`loss≈ln(2)`、交换 chosen/rejected 后的符号变化和真实参数的解析梯度对照。policy 前向保持 autograd；reference 前向在 `no_grad` 内，参数不进 optimizer。每个更新保存梯度范数、参数差值范数、前后权重 hash、样本 ID 和有效 token 数；reference 的权重与 `grad is None` 在完成时再次检查。

## 在线采样、奖励与实际 RLVR 更新

每轮采样前保存一个不可变 old 检查点。生成是真的随机自回归采样，默认温度 1，没有 top-p/top-k/repetition penalty；只禁止 PAD 和 BOS，并在剩余动作上重新归一化。每步存储实际行为分布的 token log-prob，learner 用相同温度和约束重算。

reference 固定在共同的 SFT 起点；old 每轮从采样前的 policy 刷新。old、reference、奖励和优势均 detached；current 由真实模型图重算。采样期间 optimizer steps 必须为 0，old 权重不能改变。`rollouts.json` 保存原始回答、真实动作、停止原因、行为概率、reference 概率、组成员、奖励和 RNG 状态，并重新计算概率与奖励验证回放。

奖励明确包含两个分项：严格正确答案 1 分；有效整数写法且以 EOS 结束加 0.1 分。空回答、多答案、前导零、伪造/重复格式、超长或截断不会得到格式分。这个 shaping 能在正确答案稀少时提供格式信号，因而本课只能把实际更新解释成登记奖励下的策略变化。

组优势使用总体标准差：`(reward - mean) / (std + 1e-8)`。同分组直接取全 0 优势并标记无效，不偷偷补采样。目标是 token 级 clipped surrogate，先对每条回答的有效动作取平均，再对整个 batch 平均；本课不添加 KL 正则项。因此出现非零梯度时能够定位到策略项。它是在保存前缀上的局部目标，不是整条轨迹的重要性校正或通用无偏梯度保证。

更新前核对 ratio 接近 1；每轮只使用保存的轨迹更新一次，old 不会被重新计算的 current 概率覆盖。有效奖励组存在时，必须证明有限非零 policy 梯度和实际参数变化。若某个配置产生全零优势，程序记录 `skipped_zero_advantage`；整轮没有有效更新时状态为 `sampling_passed_update_no_signal`，退出码为 3，不把采样成功当作 RL 学习成功。

C 的不更新、继续 SFT、RLVR 三支路来自相同 SFT 检查点，评测预算相同。默认继续 SFT 和 RLVR 各最多 2 个 optimizer steps，但训练样本、生成与更新 token 预算不同。`summary.json` 会逐支路列出这些实际数字；这个默认短实验不能用来宣称训练方法优劣。

## 从哪些文件复查

| 文件 | 可复查的证据 |
| --- | --- |
| `config.resolved.json`、`environment.json`、`source_versions.json` | 实际参数、Python/PyTorch、CPU、源码与 Git 版本 |
| `data_manifest.json`、`evaluation_protocol.json` | 冻结 split、题族、模板、解码和评测预算 |
| `tokenizer.json`、`token_masks.json`、`checks.json` | tokenizer、真实逐位置对齐、loss/梯度/重载门禁 |
| `base_train.json`、`sft_train.json`、`dpo_train.json` | 每次真实更新、样本和有效 token、DPO 四个 log-prob |
| `rollouts.json`、`rlvr_updates.json` | 采样、组优势、old/current/reference 概率、ratio、权重变化 |
| `*_checkpoint.pt`、`rlvr_*_before.pt`、`rlvr_*_after.pt` | 可实际读取的不可变权重、tokenizer、部分阶段 optimizer/RNG |
| `*_predictions.json`、`comparisons.json` | 三面板逐题生成、基线配对改善与退化 |
| `summary.json`、`结果说明.md` | 实际完成范围、指标、预算和限制 |
| `failure.json` | 失败时的真实类型、原因、配置和时间；失败目录继续保留 |

检查点重载会比较同一真实 batch 的 logits、tokenizer 和权重 hash。结果目录中的记录使用真实 UTC 时间；UTC 字段不会被当作当地时间。统一入口父目录还保存整个进程的日志与运行记录。

## 故意制造错误并验证门禁

在已有 PyTorch 环境中执行：

```powershell
python -m unittest discover -s tests -p test_model_training.py -v
```

测试包含真实 SFT 更新、独立 CE/参数梯度、因果和 padding 注意力、四个 DPO 概率、reference 冻结、实际温度 0.7 的采样回放、clip 正负优势分支、同分组与不可覆盖检查点。它还主动制造标签错位、提示/EOS mask 错误、reference 与 policy 共用对象、policy 图被 `no_grad` 关闭、温度不匹配和概率缓存篡改，要求这些错误明确失败。

没有 PyTorch 的标准库检查环境会跳过本组模型测试；项目 PyTorch CPU 检查环境会实际执行它们。通过图与边界检查仅支持实现正确性的具体门禁，任务质量必须查看独立生成面板。

## 已运行结果与后续练习

2026-10-02 在本机 PyTorch 2.7.1、float32、单 CPU thread、seed 17 下，默认 `--mode all` 已实际完成。该次训练使用 base 120、SFT 80、DPO 20 步；RLVR 在线采样 128 条回答、287 个动作，并做出 2 次非零策略梯度更新。SFT 参数梯度两条路径最大误差为 0，logits 解析梯度最大误差约 `1.49e-8`；DPO 初始 loss 为 `0.69314718`，所有保存阶段重载一致。

这次小规模运行的 base、SFT、DPO、继续 SFT 和 RLVR 主任务都是 `1/12`，未见操作数族都是 `0/12`，copy 回归面板都是 `0/10`。因此结果支持“代码路径、概率和梯度门禁确实运行”，不能支持模型学会了算术、RLVR 优于 SFT，或已有 copy 能力被保持。其他种子和预算的输出可能不同，应以自己的逐题文件为准。

后续按次序做三项练习：先只用训练资料增加训练预算，验证小批过拟合与生成；再固定新的开发协议，只改 beta、组大小、奖励或长度中的一个变量，并保存配置差异；最后运行独立种子、匹配训练与评测成本、建立起始模型确实具备能力的回归面板并盲审失败题。每项练习都应留下新的结果目录，然后按完整验收规格判断当前证据能支持什么结论。
