## 1 固定项目问题和比较关系

项目 B 比较起始模型、SFT、从该 SFT 检查点继续 DPO。写清起点是 Base、Instruct 还是自行训练的小模型，SFT 示范和偏好对怎样产生。DPO 的 reference 默认冻结为本次 DPO 开始前的 SFT 检查点，不能暗中换成另外的模型。

## 4 阶段 01 核对真实 token label 与 mask

从实际数据选一条短回答、一条不同长度回答和一条边界样本，用实际 tokenizer 序列化。打印每个位置的 `position`、`token_id`、可读 token、角色、attention mask、label、loss mask、来源样本 ID。先关闭 packing，降低多条记录拼接带来的歧义。不得用手填 token 编号代替真实 tokenizer 输出。

| 对象 | 形状 | 本规格的含义 |
| --- | --- | --- |
| `input_ids` | `[B,L]` | 提示、回答、EOS 与 padding 的实际 token |
| `logits` | `[B,L,V]` | 模型输出的未归一化词表分数 |
| `labels` | `[B,L]` | 未移位接口中保留回答目标；忽略位置为 `-100` |
| `shifted_targets` | `[B,L-1]` | 手动路径使用 `input_ids[:,1:]` |
| `shifted_loss_mask` | `[B,L-1]` | 对目标 token 的监督选择；不是对输入 token 的角色判断 |
| `token_logprobs` | `[B,L-1]` | `log_softmax(logits[:,:-1])` 按目标 gather 后的值 |
| `sequence_logprobs` | `[B]` | 回答有效位置 log-prob 求和，不除回答长度 |

若语义序列为 `[BOS,P1,P2,A1,A2,EOS,PAD]`，手动路径的目标是 `[P1,P2,A1,A2,EOS,PAD]`，回答监督 mask 是 `[0,0,1,1,1,0]`。这是**位置示意**，不是某个 tokenizer 的实测编号。第一个回答 token 由最后一个提示位置的 logits 预测。内部已经移位的模型 loss 接收完整、未额外移位的 labels；手写路径只移位一次。attention mask、因果 mask、loss mask 分别控制 padding/可见性、未来信息和监督目标，不能互换。

把 tokenizer 模板生成的控制 token、EOS 和截断边界实际列出来。某些模板的 assistant 起始标记属于上下文，是否监督其他控制 token 需明确登记。本规格默认只监督回答内容与约定的结束 token；多轮或工具轨迹扩展时，不能把用户、工具返回文本当成策略动作。PAD 与 EOS 共用编号时，也要按位置和长度区分它们，不能按编号把真实 EOS 一起屏蔽。

### SFT 单 batch 的标量与梯度

用同一实际 batch 计算两条路径：手写 gather/mask 与所复用训练接口。均采用全批有效回答 token 平均：

$$
L_{SFT}=-\frac{\sum_{b,t}m_{bt}\ell_{bt}}{\sum_{b,t}m_{bt}},\qquad \sum_{b,t}m_{bt}>0.
$$

输出分子、分母、逐样本有效数、逐 token log-prob 和最终 loss。若库默认是序列平均或还有辅助 loss，应关闭额外项或者单独列明，不能把两个不同目标的标量拿来核对。`ignore_index` 与归约含义可核查 [PyTorch CrossEntropyLoss 文档](https://pytorch.org/docs/stable/generated/torch.nn.CrossEntropyLoss.html)。

在真实 logits 上核对监督位置的解析导数 `(softmax - one_hot)/有效token总数`；未监督位置的直接 logits 导数应为零。这不表示提示 embedding 的梯度为零：回答会通过注意力依赖提示。再对同一模型保存并清空两次 backward 的梯度，比较至少一个实际可训练参数及总体梯度差异；关闭 dropout，使用相同权重、batch、精度与归约，并在 gradient scaling、clip 和 optimizer step 前比较。可加一个选定参数的有限差分，但需记录扰动步长和数值误差，不能用一个标量公式的差分冒充整张模型计算图核验。

先以 float32、小 batch 校准误差。可预登记 `atol=1e-5`、`rtol=1e-4` 作为起始容差，实际采用的容差、最大误差和原因都要保存；低精度或量化后的门禁应单独说明，不能只把容差放大到任意误差都通过。至少一个可训练参数有有限非零梯度，优化器参数列表与预期训练方式相符。

### DPO 单 batch 的四个概率与 reference

同一提示的 chosen/rejected 使用同一个模板和截断规则，分别对完整回答的有效 token 求和，得到 `policy_chosen`、`policy_rejected`、`reference_chosen`、`reference_rejected`。标准 sigmoid DPO 的本次检查定义为

$$
u=\beta[(\ell_{\theta,+}-\ell_{\theta,-})-(\ell_{ref,+}-\ell_{ref,-})],\qquad
L_{DPO}=\operatorname{softplus}(-u).
$$

每对取一个 loss，再在 batch 上平均；不把回答求和暗换成长度平均。若选择其他 DPO 变体，另写目标与归约，再修改参照，不能沿用这套期望值。[DPO 原始论文](https://arxiv.org/abs/2305.18290)、[TRL DPO 文档](https://huggingface.co/docs/trl/dpo_trainer)。

初始化时以相同 policy/reference 权重和确定性前向核对 `u≈0`、`loss≈log(2)`；这检查的是初始化一致性，不要求后续训练仍相等。阶段 01 可用当前模型的冻结副本作诊断 reference，正式阶段 03 则从完成 SFT 的检查点重新建立并登记 reference，不沿用旧诊断缓存。检查 chosen/rejected 交换后的符号变化，保存四数和 mask 的依据。标准单对解析梯度为 `-beta*sigmoid(-u)*(grad(policy_chosen)-grad(policy_rejected))`，对多个偏好对还需 batch 平均。把该路径与实际训练器的参数梯度比较；chosen/rejected 不相同且 batch 不退化时，至少一个 policy 可训练参数应有非零有限梯度。

reference 使用 `requires_grad_(False)`，前向在 `no_grad` 中，参数不进入优化器，梯度应为 `None`，更新前后权重 hash 不变。`eval()` 关闭 dropout，但不等于关闭 autograd；policy 为做一致性检查也可以处于 eval 模式，仍须保留梯度。[PyTorch no_grad 文档](https://pytorch.org/docs/stable/generated/torch.no_grad.html)。最常见的失败是把 policy 与 reference 的整段计算一起包进 `no_grad`：四个数看起来正确，loss 却不能更新 policy。

缓存 reference log-prob 时，把参考权重、tokenizer、模板、实际 token、loss mask、截断规则的 hash 一起写入缓存键；任一变化都应使缓存失效。reference 与 policy 共享可变对象或者适配器时，仅有不同变量名不足以证明它被冻结。

## 5 阶段 02 与 03 执行 SFT 和 DPO

先在少量训练样本上做排错用的过拟合检查，确认实际监督位置、梯度和生成链路；这不是独立能力评测。保存更新前后可训练参数的差值范数及检查点，重新加载后用固定输入比较 logits 或 log-prob，在登记的数值容差内一致。用固定提示验证推理确实加载更新后的权重，避免训练 adapter 却推理 base 的错误。

正式 B 运行使用冻结的数据和预算。起始、SFT、SFT 后 DPO 都在同一评测协议下生成；记录正确率或任务质量、格式有效率、输出长度、推理成本及失败案例。DPO 的偏好准确率和隐式奖励只是训练诊断，不能代替生成后的任务质量。SFT 验证 loss 只在同一监督规则下比较，不能据不同 token mask 的 loss 宣称模型更好。

`train.jsonl` 每次 optimizer step 至少记录真实步数、已处理样本 ID、有效训练 token、loss 分项与归约、学习率、累积次数、clip 前后梯度范数、非有限值、可训练参数集合、时间与资源。明确记录 microstep 与 optimizer step，防止把梯度累积的小批次数误报为参数更新次数。退出时保存 optimizer/scheduler、sampler/data cursor 和 RNG 状态，启用 AMP 时还保存 gradient scaler。优先在 optimizer step 边界保存；若要在梯度累积中途恢复，还须保存累积梯度、microstep 与相应归约状态。中断恢复另存恢复来源，不能跳过或重复 batch 后仍宣称无差异续训。

## 6 阶段 04 先验收采样和奖励

先建立一个冻结的行为权重快照，仅做生成、打分和回放，**不调用 optimizer step**。每题保存真实生成 token；纯离线固定答案、人工编造轨迹或只有随机奖励都不算完成在线采样。可验证任务先做奖励边界检查：正确答案、错误答案、空输出、多答案、解析异常、重复或伪造格式、超长截断和超时。判分记录应含分项、解析状态、原因以及可独立复核的目标。

采样器的随机状态用于复现随机实验，但跨设备或不同内核不保证生成逐位完全相同。已经保存的 token 是概率与奖励回放的主依据；要求在同一版本和登记容差下重算它们，不用“换一个 seed 也差不多”代替一致性核验。

### 区分三种策略与实际生成分布

`old` 是本批 rollout 的采样前冻结权重；`current` 是 learner 此次要更新的 policy；`reference` 是登记的 KL 锚点。old 随批次刷新，reference 按实验配置固定；若研究 reference 刷新，必须另立变体和版本记录。old/reference 的概率是 detached 常量，current 概率来自可反向的重算。三个名称不能共用一组会被优化器原地修改的张量。

还需区分模型原始分布 $\pi_\theta$ 与温度、top-p、top-k、重复惩罚、合法 token 限制等变换后的实际行为分布 $\mu_\theta$。若 ratio 声称对实际生成分布作校正，分母必须是实际生成的行为概率；分子也必须对应已声明的目标分布。保存 `distribution_kind`、温度、截断参数、全部 logits processor、支持集及每一步实际重归一化后的 token log-prob。

**“更新前 ratio≈1”的放行检查仅在以下条件下成立：** current 与 old 是同一采样前权重快照；提示、生成 token、模板、mask、合法动作空间和数值实现匹配；分子与分母使用同一种生成分布定义；尚未执行任何更新，且 dropout 等随机前向差异已消除或计入容差。reference 无须等于 old，current/reference 的比率也不应被要求恒为 1。

第一次严格核对建议从 `temperature=1`、`top_p=1`、关闭 top-k/重复惩罚和额外 logits 变换的随机采样开始，使已声明动作空间中的实际分布与原始 softmax 对齐。若有禁止 token 或 EOS 约束，也须同时重现约束后的重归一化。greedy 的确定性行为不能直接套用这个 softmax 采样概率门禁。

例如原 logits 为 `(0,ln(3))` 时，原始 softmax 是 `(1/4,3/4)`，温度 0.5 的行为分布是 `(1/10,9/10)`。即便权重完全相同，拿原始 current 概率除温度行为 old 概率也不会得到 1；反过来，两边都缓存原始 softmax 可以得到 1，却没有证明缓存是实际行为概率。top-p 还可能令支持集变化，不能用无条件的软概率比例宣称严格重要性校正。要么按真实变换重算并说明支持集与目标，要么将采用原始概率的算法明确列为另一种目标或近似，登记局限并另验收。

## 7 阶段 05 开放真实 RL 更新

阶段 04 通过后，锁定一小批轨迹，不重新生成，先手工核对组奖励、均值、标准差和优势。登记总体或样本标准差、是否除标准差、epsilon、有效组条件以及长度归约。全对、全错或其他相同奖励组应有零中心化优势；跳过、动态补采样或保留其 KL 更新是不同规则，都要记录，不能偷偷反复采样直到得到想要的奖励。

在 learner 中以 current 可反向前向重算 log-prob；old/reference、奖励与优势均 detached。如果使用 token 级 clipped surrogate，本次登记

$$
r_{it}=\exp(\ell^{current}_{it}-\ell^{old}_{it}),\qquad
L_{PG}=-\operatorname{reduce}_{i,t}\min(r_{it}A_i,\operatorname{clip}(r_{it},1-\epsilon,1+\epsilon)A_i).
$$

`reduce` 必须写出是按每条回答平均后再平均，还是所有有效 token 一起平均；两者对长短回答权重不同。说明所选 log-prob 是原始模型概率还是变换后行为概率，与阶段 04 的声明一致。先做同快照、同分布、无更新的 `ratio≈1` 核对，再对正负优势与越界 ratio 分别核对 clipping 分支；更新后 ratio 不必仍为 1。

这里的 token ratio 在已记录前缀上定义局部 clipped surrogate，不是整条轨迹的重要性比；它也不自动校正多轮使用旧轨迹时的前缀状态分布，更不直接证明真实策略梯度或 KL 梯度无偏。应按所实现的目标解释诊断量与局限。

若保留 KL，另外保存方向、系数、估计式、归约及反向路径。常见 `exp(d)-d-1` 中 `d=log p_ref-log p_current` 的数值非负，不等于任意 old 采样、多轮更新下都无偏，更不自动说明固定动作直接反传是 KL 的无偏梯度估计。需要时使用稳定数值形式并检测溢出；不得将 NaN 改成零后写为正常更新。原始 GRPO 与不同实现的归约、KL 和 reference 规则应回到对应公式核查。[DeepSeekMath](https://arxiv.org/abs/2402.03300)、[TRL GRPO 文档](https://huggingface.co/docs/trl/grpo_trainer)。

一个更新门禁应证明：policy 至少一个可训练参数有有限非零梯度，梯度不是只来自 KL 的偶然变化；记录有效优势组数和策略项/正则项梯度诊断；reference/old 不更新；optimizer step 前后的 policy 权重不同。全零优势批次没有奖励驱动的策略梯度是正常边界，不能凭 reference 固定时出现 KL 梯度宣称“RL 学会了任务”。

`updates.jsonl` 记录 rollout IDs、old/current/reference 版本、重用次数、optimizer step、样本/有效 token 数、优势分布、零方差组比例、ratio 范围、clip fraction、KL 分项、loss、梯度范数、输出长度/截断比例、耗时和非有限检查。多轮重用 rollout 时明确 staleness；禁止每步覆盖 old 缓存，使分母悄悄变成 current。

每次更新另保存或引用逐 token 的 `old_token_logprobs`、`current_token_logprobs`、`reference_token_logprobs`、`action_mask`、`ratio_token_values` 和 reward/advantage 来源，而不只留下最大最小值。记录 `current_checkpoint_before` 与 `current_checkpoint_after` 的不可变身份及可读取产物。门禁用的少量步骤每步保存前后权重；后续若减少完整检查点频率，必须先证明可以从检查点、更新序列、optimizer/RNG 状态重建指定更新前的权重。只有 hash 而没有对应权重或可重建路径，不能完成参数梯度回放。

## 8 阶段 06 固定评测基线和消融

先对所有支路共同的起点完成冻结评测，然后训练；训练期间只在 dev 选择配置。最终 eval 包括主任务、未见题族或模板/难度的迁移任务，以及**起始模型已具备能力**的任务外回归小面板。评测协议固定 sample IDs、模板、解码、预算、停止规则、指标与人工抽样；详见[数据与评测规范](../../references/数据资产与评测交付规范.md)。

小模型在常识、翻译或长对话上若起初基本不会，不能强制用大型通用榜单判断“能力保持”。先在开发资料上选择其确有基础表现且与预期使用相关的少量任务，再冻结独立回归题。主任务提高而回归下降时一并报告；不能只展示正例。训练 reward 和 DPO 隐式 reward 不作为最终 oracle，自动判分与盲评分歧要保留原输出并复核。

每个评测条目保存 `sample_id`、`panel`、能力桶、检查点版本、prompt/输出 token、原始文本、解析结果、自动指标、盲评结果/复核、生成 token 数、耗时与失败原因。对照用相同题目的配对变化；小样本的百分比同时给出分子/分母和不确定性，不把一题波动包装成确定提升。若报告 pass@k，保存每题实际采样数和协议，不把不同 k 或 token 预算横比。

消融文件保存基础配置 hash、唯一改动、各支路起点、训练和评测预算差异、实际重复数、逐题产物位置。C 的核心结论目标为至少 3 个独立随机种子；资源不足则报告实际次数及未完成项，不复用同一轨迹充当独立重复。没有提升时区分数据泄漏、验证器问题、信号不足、实现错误、统计波动和真正无收益的假设。

## 9 阶段 07 保存恢复与验收报告

`run.json` 至少记录 `run_id`、项目、真实状态、代码 commit 和未提交 diff hash、命令及工作目录、模型/tokenizer/数据/评测版本、环境、seed、开始结束时间、退出码、资源、artifact manifest 和阶段状态。无法公开的资产只公开可验证元数据及获取条件，不把凭据写进配置或报告。

`checkpoint_manifest.json` 包含权重/adapter 文件与 hash、base 依赖、训练步数、可训练参数、optimizer/scheduler/RNG、sampler/data cursor 状态文件、启用时的 AMP scaler、保存的更新边界、tokenizer/模板和来源运行 ID。若不是 optimizer step 边界，还需累积梯度与 microstep 状态。重载后核对固定输入的 log-prob，并比较下一批样本 ID 和续跑一个更新步骤，防止只恢复权重却重复或漏掉数据；区分数值可重放和跨设备逐位可复现。报告明确哪些结果只在一个设备、一种精度和一个小任务上成立。

提交报告顺序为问题和假设、数据与协议、基线、真实结果、消融、不确定性、失败样例、可以支持的结论、仍需验证的解释。字段 `completed_stages` 来自实际阶段回执；一个设计完善但尚未运行的项目应写 `specification_ready`，不能写 `training_complete`。

## 10 用失败记录验收排错能力

| 植入或观察到的失败 | 应由哪些证据定位 | 本次不得放行的理由 |
| --- | --- | --- |
| labels 外部再次移位 | 逐位置 token/label/mask 与同 batch loss | 形状正确但预测的是隔一个 token |
| EOS 与 PAD 共用编号，全部按编号屏蔽 | 真实长度、角色和 EOS 有效计数 | 回答的结束监督被错误删除 |
| prompt token 进入回答 loss | 角色表、mask 统计、直接 logits 导数 | 优化目标已与登记的 SFT 目标不同 |
| policy 被包进 `no_grad` | `loss.requires_grad`、参数 grad、更新前后 hash | loss 有值而 policy 没有学习 |
| reference 共用会更新的适配器 | reference 身份、参数 hash 和缓存键 | DPO/KL 锚点发生未登记变化 |
| 温度/top-p 与缓存概率不匹配 | 行为配置、逐步重归一化、同快照概率回放 | ratio 的重要性解释不成立，原始 softmax 比值不能补救 |
| 在 RL learner 内重算并覆盖 old | 采样快照 hash、更新批次版本与缓存 hash | 每步分母漂移，clip 诊断失去预定含义 |
| 全零优势仍称奖励驱动更新成功 | 整组 reward、优势、策略与 KL 梯度分项 | 可能只有正则项更新，没有奖励信号 |
| 训练 reward 增高但独立正确率下降 | 冻结逐题评测、奖励分歧与作弊样例 | 训练目标改善不能替代最终任务验收 |
| 用 eval 反复挑 beta 或题目 | split lock、配置选择日志、评测历史 | eval 已成为开发数据，需重新定义报告集 |

至少主动制造标签错位、reference/梯度边界错误和采样概率不匹配三个失败例，证明门禁能拒绝它们，然后恢复正确配置。失败日志包括触发条件、检测字段、修复和复查结果；不要求把错误配置用于长时间训练。完成这些证据后，才能把真实模型实验与已经通过的数学核算一起写进作品说明。
