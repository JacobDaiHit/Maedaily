# 数据资产实验：过滤、题族切分与逐字重建

[实验目录](README.md) · [数据与评测交付规范](../../references/数据资产与评测交付规范.md) · [预训练与数据治理](../../transformer/chapters/04_预训练数据与Scaling.md)

这节课用 50 条原创教学记录练习数据管线。你会看到来源与许可记录、质量过滤、精确重复、题族切分和文件 hash 怎样连接到一个可重建的数据资产。先运行小例子，再把相同的审计方法用于项目 B/C 的真实数据；完整交付要求见上面的规范。

配套程序是 [data_asset_lab.py](../../scripts/data_asset_lab.py)，只用 Python 标准库。示例故意放入重复、空回答、过长输入、错标签和冲突标签。它只核对输入中提供的标准答案；真实任务仍需验证器和人工复核。

## 1 运行与查看产物

在项目根目录运行：

```powershell
python scripts/run_lesson.py data-asset
```

统一入口会选择已有可用的 Python，终端打印本次独立目录。父目录保存 `console.txt`、`run.json`、`结果说明.txt`；五份实验产物在其 `artifacts/` 子目录：

| 文件 | 用它回答什么问题 |
| --- | --- |
| `raw.jsonl` | 本轮实际处理了哪些原始记录？保存规范化 JSON 序列化后的原记录，字段内容尚未做文本清洗 |
| `data.jsonl` | 保留了哪些样本？来源、许可、原始记录 hash、题族组、split 和字符数是什么？ |
| `audit.jsonl` | 每条输入被保留还是过滤，原因是什么？重复记录保留了哪个 ID？ |
| `manifest.json` | 输入、脚本和输出版本是什么？配置、阶段数量、来源保留率怎样变化？ |
| `summary.json` | 数量、过滤原因、划分与重建检查是否通过？ |

目录已有内容时程序拒绝覆盖。下面的直接入口用于改变输入或阈值；统一入口运行默认教学配置。

```powershell
python scripts/data_asset_lab.py --help
python scripts/data_asset_lab.py --seed 7 --max-chars 512
```

## 2 输入契约与处理顺序

输入是 UTF-8 JSONL，每行一个对象。`id`、`family_id`、`source`、`license`、`prompt`、`completion` 必须为字符串；前四项还必须非空。`expected_answer` 可省略，提供时必须为字符串。例如：

```json
{"id":"addition-1-a","family_id":"addition-1","source":"original_teaching","license":"teaching_placeholder","prompt":"Compute 1 + 1.","completion":"2","expected_answer":"2"}
```

`teaching_placeholder` 只是这套自编示例的教学标记。接入真实数据时填写可定位的来源与实际许可记录，并按数据交付规范保留版本与用途；一个字符串不能证明外部数据已经获得使用许可。不同数据用途有不同 schema：这个实验的 prompt/completion 格式适合示范数据练习，RL prompt-only 数据、偏好对与评测集使用规范中的对应契约。

管线先拒绝错误 schema、重复 ID、重复 JSON 字段与非有限 JSON 数字，之后才创建输出。对 prompt/completion 使用 Unicode NFC 和两端空白去除，保留大小写与内部空白；代码和符号任务可能依赖这些字符。

分组在质量过滤前执行：同一 `family_id` 或相同清洗后 prompt 的样本合并成连通组。这会把“跨来源、另写题族名”的相同问题接回原组；过滤掉桥接样本后也保留分组关系。人工已标注的改写题共用题族，程序没有识别任意语义近重复的能力。

随后按以下顺序判定，每条记录保存一个首个过滤原因：

1. prompt 或 completion 为空；
2. 两段文本的字符总数超过 `--max-chars`；
3. 同一清洗后 prompt 对应多个不同的已提供标准答案，相关记录全部过滤；
4. completion 与已提供标准答案不一致；
5. 清洗后的 prompt/completion 完全相同，只保留字典序最小的合格 ID。

保留数据按 `seed + group_id` 的 hash 桶分为 train/validation/test，桶范围是 70/15/15。划分以组为单位，比例是近似目标；小数据不保证恰好该比例，也不保证每个 split 非空。正式项目要检查独立题族数、覆盖与污染，并在训练前固定划分。增删原始组成员可能改变 group hash，因此新增数据必须发布新版本。

`character_count` 是字符数；`token_count` 和 `tokenizer_id` 明确为空。真实模型的 token 预算、chat template、截断和监督 mask 要由实际 tokenizer 另行验收，不能从此处的字符数推算。

## 3 默认例子的实际结果

2026-10-02 使用 Python 3.13.5、seed=7、max_chars=512，统一入口实跑通过：

| 项目 | 实际数量 |
| --- | ---: |
| 原始记录 | 50 |
| 保留记录 | 44 |
| 过滤记录 | 6 |
| 保留数据的连通组 | 40 |
| train / validation / test | 28 / 6 / 10 |
| 冲突标准答案 | 2 |
| 空文本 / 过长 / 错标签 / 精确重复 | 各 1 |

检查包括：ID 唯一、每条输入有审计决定、连通组不跨 split、同输入与配置构建的四份核心文件逐字相同。它们说明这套处理规则按预期执行；数据质量是否足够支持模型学习，仍需真实模型对照和独立评测。

`canonical_input_sha256` 对规范化 JSON 序列化的有序原始记录计算 hash，包含字段内容和记录顺序，忽略输入文件的排版空白。`raw_record_sha256` 同样针对规范化原记录。它们不是原输入文件字节的 hash；若业务要求保留文件原貌，应额外保存原文件及其字节 hash。输出 `data.jsonl`/`audit.jsonl` 与管线脚本各有实际字节 hash。

## 4 改一个条件，再解释变化

先预测把字符上限从 512 改成 2000 会保留哪条记录、改变哪些数量，再运行：

```powershell
python scripts/data_asset_lab.py --seed 7 --max-chars 2000
```

每次输出新目录。比较两轮 `audit.jsonl` 与 `manifest.json`，检查长样本的决定、来源保留率和 split；其他过滤规则仍然生效。不能因为保留数量增加就称质量提升，应说明接受长输入对真实 tokenizer、截断和预算有什么影响。

要验证跨进程重建，用第一轮打印的目录替换下面的路径，并保持配置相同：

```powershell
python scripts/data_asset_lab.py --input 'study_runs/本次目录/artifacts/raw.jsonl' --seed 7 --max-chars 512
```

比较两轮 `raw.jsonl`、`data.jsonl`、`audit.jsonl`、`manifest.json` 的 SHA256。相同代码、输入顺序和配置应相同；代码版本或原始组改变时，manifest 与相应产物 hash 也应变化。运行日志的时间不属于这个逐字重建契约。

完成本课时提交两轮数量与过滤差异、一个重复/题族组的去向、一个冲突标签案例、四份文件 hash 的比较，以及当前管线尚未覆盖的一种风险。然后按[真实模型训练与验收](真实模型训练与验收.md)检查 tokenizer 和监督范围，把可重建数据资产接入实际训练。
